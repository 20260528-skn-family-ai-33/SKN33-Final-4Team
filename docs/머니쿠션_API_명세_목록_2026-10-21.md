# 머니쿠션 API 명세 목록

> 2026-10-21 · 기준 문서: `docs/API_RULES.md`(공통 규칙), `docs/머니쿠션_API_명세_작성_순서_2026-10-21.docx`(주소 초안)
> 반영한 결정: 챗봇 소비 분석 = LLM 라우터가 문장 해석 + 서버 집계 + 템플릿 답변 (요구사항 CHT-006·RPT-001·RPT-004·AGT-001, 10/21) · 내 정보·급여는 예산 ML 결과 후 작성 · 알림·소비 분석 화면은 2차
> 명세 작성 마감 **10/24(금)**

## 읽는 법

**굵은 글씨 = 지금 명세를 쓸 수 있는 API**

| 상태 | 뜻 |
|---|---|
| **지금** | 보내는 값·받는 값·실패 상황까지 초안을 쓴다 |
| **기본만** | 확실한 항목만 쓰고, 미정인 부분은 `확인 필요: 내용 / 확인할 사람`으로 남긴다 |
| ML 후 | 예산 ML 결과·새 온보딩 흐름이 정해진 뒤 쓴다 |
| 결정 후 | ML과 상관없이 따로 정할 것이 남아 있다 |
| 2·3차 | 후속 단계에서 범위를 다시 정한 뒤 쓴다 |

> ML 후·결정 후·2·3차는 이번(10/24) 작성 대상이 아니다. 추천 예산 금액이나 쿠션 배분 규칙을 각자 추측해서 채우지 않는다.
> 공통 기준과 다른 내용을 발견하면 직접 고치지 말고 `확인 필요`에 적어 나은에게 알린다. 공통 문서는 나은이 모아서 고친다.

## 0. 공통 규칙 (요약 · 원본은 `docs/API_RULES.md`)

| 항목 | 규칙 |
|---|---|
| 주소 | `/api/` + 화면 주소 모양, 끝에 `/` (`/api/finance/transactions/<id>/`) |
| 방식 | 읽기 `GET` · 만들기·실행 `POST` · 일부 수정 `PATCH` · 묶음 저장 `PUT` · 삭제·중지 `DELETE` |
| 키 이름 | React `camelCase` ↔ Django `snake_case` 자동 변환 |
| 돈 · 퍼센트 | 원 단위 정수 · 비율은 0~100 숫자 (증감률은 예외: 음수·100 초과 가능, 비교 대상이 0원이면 `null`) |
| 날짜 · 시각 | `YYYY-MM-DD` · ISO 8601 한국 시간 |
| ID | UUID 문자열 |
| 빈 값 | `null` |
| 로그인 · 보안 | Django 세션 쿠키 + CSRF 토큰 (`X-CSRFToken`) |
| 목록 응답 | `{ "items": [...] }` |
| 에러 응답 | `{ "error": { "code", "message", "fields" } }` · 로그인 안 함 = 403 `not_authenticated` · 남의 데이터 = 404 |
| 비공개 값 | 은행 비밀번호·CODEF 키·`connectedId`·계좌번호 원문은 응답에 넣지 않음 (`****1234`) |

**API 하나마다 적을 칸:** 어떤 기능(어느 화면, 무엇을 누를 때) · 어디로(방식 + 주소) · 무엇을 보내나(이름·타입·필수·범위) · 무엇을 받나(값의 뜻 + 예시) · 실패하면(에러 코드 + 화면 안내) · 확인 필요(누구와 무엇을)

**`POST /api/chat/messages/` 지금 쓸 수 있는 부분**

- 요청: 문장 입력과 추천 선택지 누르기를 한 주소로 받는다.
- 라우팅 결과: 의도 코드 `spending`(소비 분석) · `budget`(예산 조정) · `big`(큰 지출 상담, 1차는 '준비 중') · `out`(범위 밖) · `unknown`(알 수 없음). 요청 정보(slots): 기간 · 비교 기준 · 카테고리 · 금액 · 늘림/줄임 (AGT-001)
- 소비 분석 답변 종류(CHT-006): 카테고리 없음 → 전체 / 카테고리 있음 → 그 카테고리 / 비교 기준 있음 → 지난달 대비 추가. 기간이 없으면 이번 급여주기, 비교 기준 기본은 지난달
- 소비 분석 카드의 숫자는 서버 집계(RPT-001), 문장은 템플릿(RPT-004 1차 범위). LLM은 문장 해석에만 쓴다.
- `prevDiffRate`(증감률)는 음수·100 초과가 가능하고, 지난달이 0원이면 `null` + 금액 변화만 보여 준다(RPT-001).

```json
// 요청 (둘 중 하나)
{ "conversationId": null, "text": "지난달보다 식비 얼마 썼어?" }
{ "conversationId": "3f2c…", "choice": "spending" }

// 응답 — 소비 분석 예시 (칸 이름은 명세 작성 때 확정)
{
  "conversationId": "3f2c…",
  "route": { "intent": "spending", "slots": { "category": "FOOD", "compare": "prev_month" } },
  "messages": [
    {
      "role": "bot",
      "contentType": "card",
      "content": {
        "kind": "spending",
        "period": { "from": "2026-09-25", "to": "2026-10-24" },
        "compare": { "from": "2026-08-25", "to": "2026-09-24" },
        "total": 1320000,
        "categories": [ { "code": "FOOD", "name": "식비", "amount": 420000, "ratio": 32, "prevDiff": 40000, "prevDiffRate": 11 } ],
        "unclassifiedAmount": 35000,
        "lines": [ "지난달보다 식비를 4만 원(11%) 더 썼어요." ],
        "updatedAt": "2026-10-21T16:20:00+09:00"
      }
    }
  ]
}
```

> 1차는 소비 집계용 API를 따로 만들지 않는다. 챗봇 서버가 집계 함수를 바로 부른다. 2차 소비 분석 화면 때 `GET /api/reports/spending/`을 만들고 같은 집계·템플릿을 쓴다.

## 9. 명세 담당

> 굵은 것(지금 · 기본만) = 10/24까지 작성. 이 표는 **담당 확인용**이고, 실제 API와 상태는 1~7번을 본다.

| 담당 | 맡는 묶음 | 지금 쓸 API | 나중에 쓸 것 |
|---|---|---|---|
| **김나은** | 4 고정지출 · 6 홈 | **7개** | 5 내 정보·온보딩·예산 전체 (ML 후), 돌발 지출 |
| **김혜리** | 2 동의·계좌·연결 · 3 거래 · 7 챗봇 | **11개** | 금융기관 인증·다시 불러오기, 조정안 승인, 알림 |
| **권세진** | 1 공통·인증 · 2 카드·대출·청구서 · 7 소비 분석 카드 칸 | **10개** + 카드 칸 | 비밀번호 재설정, 소비 분석 화면, 큰 지출 상담 |

> 소비 분석 카드: 세진이 들어갈 항목과 예시를 써서 혜리에게 전달 → 혜리가 `chat.md`에 반영 (`chat.md` 최종 편집은 혜리, 작업 진행 확인 API 포함).
