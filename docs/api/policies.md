# 청년 정책 API 명세

> 담당: 권세진 · 명세 상태: 초안 · 개발 상태: 실제 기능 (저장한 정책)
> 공통 규칙은 `docs/API_RULES.md`를 따른다 (camelCase · 원 단위 정수 · UUID · 세션 쿠키 + CSRF · 에러 모양)

청년 정책 추천은 채팅(`docs/api/chat.md`, 정책 담당)으로 한다. 이 문서는 사는 지역 목록과 추천받은 정책을 저장(북마크)하는 API 다.
마이페이지(`/my`)의 [내 돈 관리] 아래에는 [저장한 정책 보기] 메뉴만 보여 준다.
메뉴를 누르면 별도 화면(`/my/policies`)에서 최신 저장순 목록·신청 상태·마감일·저장일·공고 원문 링크를 조회한다.
수집 종료된 정책도 안내와 함께 남기며, 목록 조회 실패와 저장한 정책이 없는 상태를 구분한다.

채팅 정책 카드(2026-11-12 베타 피드백): 새 추천·상세·저장 목록의 `content.sections[].policyNo`로 정책을 식별한다.
한 번에 한 정책을 보여 주고 이전·다음 버튼으로 같은 답변의 정책들을 넘긴다. 화면 제목에서는 추천 순번을 빼고 정책명만 표시한다. 카드의 [저장]은
`PUT /api/policies/<policyNo>/saved/`를 사용하므로 후속 질문 뒤에도 누를 수 있고 대화 turn을 변경하지 않는다.
저장 상태는 `GET /api/policies/saved/`로 확인한다. 카드 안에 저장 버튼이 있는 답변에서는 기존 [N번 저장] 칩을 숨긴다.
정책번호가 없는 기존 메시지는 종전 표시·선택지 처리를 유지하며, 지난 대화 선택지의 turn 검증은 그대로 둔다.

상세 답변은 원문을 길이 제한으로 버리지 않고 화면에서 긴 항목을 접어 보여 준다. 제출 서류 전용 필드뿐 아니라
신청 방법·추가 자격·기타 안내에 명시된 서류 관련 원문도 출처 항목을 붙여 보여 준다. 전용 필드가 비었으면
전체 서류 목록을 확인한 것으로 표현하지 않는다. 지원 확답 질문은 대상 정책을 고른 뒤에도 의도를 유지해
신청만으로 확정되지 않는다고 답하고, 자격·심사 항목 및 확인 경로를 안내한다.

**주소 속 정책번호**: 정책은 온통청년 공식 정책번호(20자리 숫자 문자열)가 ID 라서 UUID 가 아니다 (`policy` 표의 예외, `docs/DB_MODELS.md`).
없는 번호 · 형식이 틀린 번호는 404 다.

## 사는 지역 목록

`GET /api/policies/regions/` — 온보딩 · 내 정보의 사는 지역 드롭다운(시도 → 시군구). 로그인 필요(403 `not_authenticated`). 2026-11-11.

시도 16개와 그 아래 고를 수 있는 시군구(`policies/data/regions.json` 의 final)를 돌려준다. 구가 있는 시는 구까지("화성시 동탄구"), 세종은 시도 자신이 시군구다.
`regions[].code` 를 내 정보 `PUT /api/profile/` 의 `regionCode` 로 보낸다 (`docs/api/profile.md`).

```json
{
  "items": [
    {"code": "11000", "name": "서울특별시", "regions": [{"code": "11110", "name": "종로구"}, {"code": "11620", "name": "관악구"}]},
    {"code": "36110", "name": "세종특별자치시", "regions": [{"code": "36110", "name": "세종특별자치시"}]}
  ]
}
```

채팅에서의 사는 지역: 지역 없이 물으면 대화에서 처음 한 번 "가입 지역(…)으로 찾으시는 거 맞나요?"를 묻는다. 지역을 말하거나 다른 지역을 고르면 그 지역으로 찾고 [다음에도 ○○구로 찾기]를 보이며, 누르면 내 정보의 `region_code` 를 바꾼다 (채팅 엔진이 대화 저장과 같은 트랜잭션에서).

## 저장한 정책 목록

| 칸 | 내용 |
|---|---|
| 어떤 기능 | 저장한 정책을 최신순으로 볼 때 (마이페이지 — 화면 미정) |
| 어디로 | `GET /api/policies/saved/` |
| 로그인 필요 | O |
| 명세 상태 | 초안 |

**받는 값 (200)**

| 이름 | 타입 | 뜻 |
|---|---|---|
| `items[].savedPolicyId` | UUID | 저장 한 건의 ID |
| `items[].policyNo` | 문자 | 정책번호 |
| `items[].name` | 문자 | 정책명 (DB 값 그대로) |
| `items[].applyState` | 문자 | `open` 신청 중 · `always` 상시 · `upcoming` 신청 예정 · `unknown` 기간 확인 필요 · `closed` 마감 |
| `items[].applyEnd` | 날짜 \| null | 마지막 신청 마감일. 상시 · 기간 모름이면 `null` |
| `items[].link` | 문자 \| null | 신청 주소, 없으면 참고 주소, 둘 다 없으면 `null` |
| `items[].active` | 참/거짓 | 정책 수집에서 사라졌으면 `false` (저장 기록은 남는다) |
| `items[].savedAt` | 시각 | 저장한 시각 |

```json
{
  "items": [
    {
      "savedPolicyId": "3f2c9a10-…",
      "policyNo": "20261021005400214208",
      "name": "2026 청년 월세 지원",
      "applyState": "open",
      "applyEnd": "2026-12-31",
      "link": "https://…",
      "active": true,
      "savedAt": "2026-11-10T15:30:00+09:00"
    }
  ]
}
```

- 마감 · 수집 종료된 정책도 지우지 않고 상태로 보여 준다. 화면에서 어떻게 표시할지는 마이페이지를 정할 때 정한다.

## 정책 저장

| 칸 | 내용 |
|---|---|
| 어떤 기능 | 추천받은 정책이 마음에 들어 저장할 때 (정책 카드 화면 — 미정. 채팅에서는 [N번 저장] 버튼이 같은 일을 한다) |
| 어디로 | `PUT /api/policies/<policyNo>/saved/` |
| 로그인 필요 | O |
| 명세 상태 | 초안 |

**보내는 값**: 없음 (본문을 보낸다면 `{}` 만. 다른 칸이 있으면 400 `invalid`)

**받는 값 (200)**: 위 목록의 한 칸과 같은 모양

- **이미 저장한 정책이어도 200** 으로 같은 칸을 돌려준다 (두 번 눌러도 한 줄). 그래서 요청 번호(`Idempotency-Key`)가 필요 없다.

**실패하면**

| 상황 | 상태 | `code` | 화면 안내 |
|---|---|---|---|
| 없는 정책번호 · 수집이 끝난(비활성) 정책 | 404 | `not_found` | "찾을 수 없어요" |
| 본문에 칸을 보냄 | 400 | `invalid` | 개발 중 버그 |

## 정책 저장 취소

| 칸 | 내용 |
|---|---|
| 어떤 기능 | 저장한 정책을 목록에서 뺄 때 |
| 어디로 | `DELETE /api/policies/<policyNo>/saved/` |
| 로그인 필요 | O |
| 명세 상태 | 초안 |

**받는 값 (204)**: 본문 없음

- **저장돼 있지 않아도 204** (이미 원하는 상태). 수집이 끝난 정책도 취소할 수 있다.

**실패하면**

| 상황 | 상태 | `code` | 화면 안내 |
|---|---|---|---|
| 없는 정책번호 | 404 | `not_found` | "찾을 수 없어요" |

**확인 필요**

- 마이페이지에서 저장 목록을 어디에 · 어떻게 보여 줄지 (마감 · 비활성 정책 표시 포함) → 팀 회의
- OpenAPI(`docs/openapi/parts/`) 명세 추가 → 화면이 정해지면
