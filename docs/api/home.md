### 10/21 결정

| 번호 | 질문 | 결정 |
|---|---|---|
| H-01 | 월급이 일찍 · 늦게 들어오면 주기는? | **주기는 항상 사용자가 설정한 월급날에 바뀐다.** 실제 입금은 주기를 바꾸지 않고 상태로만 알린다. 미리 들어온 월급은 지난 주기 예산에 넣지 않고 따로 빼 두며, 늦게 들어오는 동안은 "아직 안 들어왔어요"로 알린다 (아래 ①). 처음엔 '입금일에 새 주기'로 정했다가 같은 날 바꿈 — 늦게 오면 지난 주기가 길어지고, 그사이 쓴 이번 달 생활비가 지난달 초과로 잡혀서 |
| H-02 | 저축용으로 고른 입출금 계좌도 잔액 합계에 넣나 | **넣는다.** 화면 이름이 '입출금 계좌 잔액'이고, 쓸 수 있는 돈은 예산 영역이 따로 보여 준다 |
| H-03 | 확인할 거래 수는 어떻게 세나 (10/22 혜리) | **전체 기간**에서 카테고리가 '확인 필요'(`UNCLASSIFIED`)인 **소비 거래** 수. 거래 목록 `GET /api/finance/transactions/?category=UNCLASSIFIED`(기간 없이)의 `summary.needsReviewCount`와 같은 값이다. 목록은 최신순 |
| H-05 | 출금일 모르는 고정지출을 홈에서 알리나 | **알린다.** `needsPaydayCount` → "출금일을 확인할 고정지출 N건 ›" 알림 줄 |
| H-06 | 예산이 없을 때 · 온보딩 전 홈 | ① 예산이 없으면(`budget: null`) 파란 카드 자리에 **안내 카드**. ② 온보딩을 안 끝냈으면 **홈을 열지 않고 온보딩으로 보낸다**(화면이 판단, 아래 ⑤) |
| H-07 | DB 코드 (10/22 혜리 · 나은) | API 값 = DB 값, 소문자 영어. 이 명세가 쓰는 것: 입출금 계좌 `bank_account.account_type = demand`(CODEF 예금 구분 `11`), 연결 상태 `connection.status` = `connected` · `relogin` · `disconnected`, 입금 `financial_transaction.direction = in`. 전체 코드표는 [결정기록](../결정기록_2026-10-21.md) 3-1 |

### 계산 규칙

**① 급여 주기 (`period`) — BUD-004 · H-01**

> **주기는 항상 사용자가 설정한 월급날에 바뀐다.** 실제 입금은 주기를 바꾸지 않고, 들어왔는지 · 미리 들어왔는지 · 아직인지를 **알려 주는 데만** 쓴다.

*월급날*

- 기준은 `FinancialProfile.payday`(매월 급여일 1~31). 비어 있으면 `period: null`, `mustPay: []`.
- 그 달에 급여일이 없으면 **그 달 말일**(31일 → 9/30, 2/28, 윤년 2/29). [공통 규칙 '매월 N일'](../API_RULES.md#한눈에-보기)과 같다. 주말 · 공휴일 이동은 계산하지 않는다.
- 오늘이 이번 달 월급날 **이후거나 같은 날**이면 이번 달 월급날이 시작일, 아니면 지난달 월급날이 시작일이다. 다음 월급날 전날이 마지막 날이다.

| 급여일 | 오늘 | startDate | endDate | nextPayday | dday |
|---|---|---|---|---|---|
| 25 | 10/21 | 09-25 | 10-24 | 10-25 | 4 |
| 25 | 10/25 (월급날, 입금 전이어도) | 10-25 | 11-24 | 11-25 | 31 |
| 31 | 2027/02/10 | 2027-01-31 | 2027-02-27 | 2027-02-28 | 18 |

*월급 입금 찾기* (상태 표시용, 시작 값)

| 조건 | 값 |
|---|---|
| 어디로 | 내 관리 대상 입출금 계좌(`account_type = demand`, 연결 해제 제외)로 들어온 **입금**(`direction = in`) |
| 얼마 | **월 실수령액(`monthly_take_home_income`)의 80% 이상** — 중고거래 같은 작은 입금은 월급으로 보지 않는다 |
| 제외 | **내 계좌끼리 옮긴 돈** — 같은 날 같은 금액이 내 다른 계좌에서 나간 입금 (적금 해지 후 옮긴 돈 등) |
| 이번 주기 월급 | 이번 월급날 **7일 전**(명절에 당겨 주는 경우) ~ 다음 월급날 8일 전 사이의 첫 입금 |
| 다음 달 월급이 미리 옴 | 다음 월급날 7일 전 ~ 오늘 사이의 첫 입금 → `nextSalaryEarlyOn` |

*경우별 처리* (급여일 25일, 실수령액 250만 원)

| 경우 | 주기 | `salaryState` · 표시 | 예산(ML 후)에서 할 일 |
|---|---|---|---|
| 제때 (25일 입금) | 25일에 새 주기 | `received` | 평소대로 |
| **미리** (명절 전 12/18 입금) | 12/24까지 지난 주기, **12/25에 새 주기** | 지난 주기: `nextSalaryEarlyOn = 12/18` "미리 들어왔어요" / 새 주기: `received` · `salaryReceivedOn = 12/18` | 지난 주기의 쓸 수 있는 돈에 이 월급을 **넣지 않는다** (따로 빼 둠, BUD-004) |
| **늦게** (10/30 입금, 회사 사정 · 명절 후) | 10/25에 새 주기 | 10/25~29 `waiting` "월급이 아직 안 들어왔어요" → 10/30부터 `received` | 들어오기 전까지 오늘 쓸 수 있는 돈을 **실제 잔액을 넘지 않게** |
| 끝까지 안 들어옴 | 다음 월급날에 또 새 주기 | 계속 `waiting` | 위와 같음 |
| 실수령액을 안 넣음 | 날짜대로 | `unknown` | — |

- **월급날 ~ 실제 입금일 사이에 쓴 돈은 새 주기 생활비다.** 예산은 '어느 기간에 썼나'를 보지 '어느 돈으로 냈나'를 보지 않는다. 10/25~29에 쓴 밥값은 월급이 언제 들어오든 이번 달 생활비다.
- **저장**: 주기는 `budget_cycle`에 남긴다. `starts_on` = 월급날, `ends_before` = `expected_payday` = 다음 월급날, `status` = 지금 주기 `active` · 끝난 주기 `closed`(`budget_cycle.status` 코드 — 이 명세에서 정함), `confirmed_income` = 찾은 이번 달 월급 금액(못 찾으면 비움).
- **언제 확인하나**: 매일 도는 작업 없이 **홈 · 예산을 열 때** 확인한다(C-15와 같은 방식). 같은 주기는 `budget_cycle`(회원 · 시작일) UNIQUE로 한 번만 생긴다.
- 이번 명세의 '이번 주기'는 [fixed.md](fixed.md)의 '이번 주기(급여일 ~ 다음 급여일 전날)'와 같다.

**② 계좌 잔액 (`balance`) — H-02**

| 들어가는 계좌 | 빠지는 계좌 |
|---|---|
| 내 계좌 · 관리 대상으로 고른 것(`is_selected`) · 입출금 계좌(`account_type = demand`) — **저축 용도로 고른 입출금 계좌도 포함** | 관리 대상이 아닌 계좌 · 연결 해제(`disconnected`)된 계좌 · 예적금 · 대출 · 외화 계좌 |

- 잔액은 `BankAccount.balance`(잔액)를 쓴다. 출금 가능액(`withdrawable_amount`)은 쓰지 않는다.
- 잔액을 못 받은 계좌(`balance`가 비어 있음)는 **0으로 더하지 않고** `unknownCount`로 센다(UI-002: 미수집 잔액은 값 없음).
- 다시 연결이 필요한(`relogin`) 계좌는 마지막으로 받은 잔액을 합계에 넣고 `reloginCount`로 센다. 화면은 "다시 연결 필요"와 기준 시각을 같이 보여 준다.
- 고정지출 결제 계좌 선택에서는 저축 용도 계좌를 빼지만(fixed.md), 잔액 합계에는 넣는다. 잔액은 '내 입출금 계좌에 있는 돈'이고, '쓸 수 있는 돈'은 예산 영역이 따로 보여 주기 때문이다.
- **화면에서 금액을 따로 계산하지 않는다**(UI-002). 합계 · 개수는 서버가 준 값을 그대로 쓴다.

**③ 알림 줄 수 (`pendingCount` · `needsPaydayCount`)**

- `pendingCount` (H-03): **전체 기간**에서 카테고리가 '확인 필요'(`UNCLASSIFIED`)인 소비 거래 수. 거래 목록에 들어가는 거래와 같다(출금 중 소비 거래만, 카드값과 같은 구매로 중복된 계좌 출금은 제외). 서버는 거래 목록 `GET /api/finance/transactions/?category=UNCLASSIFIED`(기간 없이)의 `summary.needsReviewCount`와 **같은 조회**로 센다 — 홈 알림을 누르면 이 목록(최신순)으로 가므로 숫자와 목록이 항상 같다. 지난달에 처리하지 못한 거래도 사라지지 않는다. 거래 분류 ML 전에는 대부분의 소비 거래가 '확인 필요'라 숫자가 클 수 있다.
- `needsPaydayCount` (H-05): 내 고정지출 중 **확정(`confirmed`)이고 출금일(`payment_day`)이 비어 있는 것**의 수. 계좌 · 카드 · 모름 모두 센다(카드도 출금일이 있어야 '이 결제가 맞나요?'를 물을 수 있음, fixed.md C-14). 후보 · 중지 · 무시는 세지 않는다.
- 화면: 두 줄 모두 0이면 숨긴다. "카테고리를 확인할 거래 4건 ›" → 거래 목록, "출금일을 확인할 고정지출 1건 ›" → 고정지출 화면.

**④ 꼭 나갈 돈 (`mustPay`) — COM-004 · C-08 · C-15**

- 납부 예정(`PaymentDue`) 중 아래를 모두 만족하는 것만 보여 준다.

| 조건 | 값 |
|---|---|
| 내 것 | `user` = 로그인한 회원 |
| 유효 | `obligation_state = active` (취소된 것 제외) |
| 아직 다 안 냄 | `payment_state` 가 `unpaid` · `partial` · `needs_review` (`paid` 제외) |
| 언제 것까지 | **이번 주기 회차 + 지난 주기에 아직 다 안 낸 회차**. 지난 주기 미납은 **다음 월급날 전까지(이번 주기 내내)** 보여 주고, 새 주기가 시작되면(그다음 월급날) 홈에서 빠진다. 기록은 `needs_review`로 남는다 (10/22 PR #26 리뷰, 아래 '미납 안내') |
| 종류 | 이번 명세는 `recurring`(고정지출)만. 카드 청구서 · 대출은 H-04 |

- 회차(납부 예정 하나)는 주기와 같은 구간(월급날 ~ 다음 월급날 전날)으로 나눈다. 새 주기가 시작되면(월급이 아직이어도) 새 회차 것을 만든다.
- 정렬: 나갈 날(`dueDate`)이 빠른 순 → 금액이 큰 순.
- **카드로 내는 고정지출은 여기 없다.** 카드 청구서 안에 들어 있어서 따로 세지 않는다(C-08). 출금일을 모르는 고정지출도 납부 예정이 없어서 여기 없고, 대신 `needsPaydayCount`로 알린다(H-05).
- **미납 안내 (10/22 PR #26 리뷰)** — 출금 **연결** 기간과 미납 **안내** 기간을 나눈다.

  | 시점 (출금일 25일 예) | 상태 | 홈 '꼭 나갈 돈' 표시 |
  |---|---|---|
  | 25일 전 | `unpaid` | "10.25 · 국민 급여통장" |
  | 25 ~ 28일 (출금일 +3일까지) | `unpaid` | **"출금 확인 중"** — 자동 연결(±3일)을 기다리는 중 |
  | 29일부터 다음 월급날 전까지 | **`needs_review`** | **"미납 확인 필요 ›"** — 누르면 고정지출 화면의 [고르기] |
  | 다음 월급날부터 | `needs_review` 그대로 | 홈에서 빠짐 (기록은 남음) |

  - `unpaid` → `needs_review` 바꾸기는 매일 도는 작업 없이 **홈 · 고정지출을 열 때** 한다(C-15와 같은 방식).
  - 늦게 낸 출금(±3일 밖)은 자동으로 연결하지 않는다. 사용자가 고정지출 화면의 [고르기]로 고르면 `paid`가 되어 홈에서 빠진다([fixed.md](fixed.md) '미납 확인 필요 회차의 고르기').
  - 1차에는 "따로 냈어요"처럼 끄는 버튼이 없다. 그래서 다음 월급날까지만 보여 준다.
- 주기 중간에 홈을 처음 열면 이미 지난 날짜의 회차(예: 9/30 통신비)가 `unpaid`로 생길 수 있다. 실제 출금이 있으면 출금 매칭이 연결해 `paid`로 바꾸고, 그 전까지는 "출금 확인 중"이다.
- **이 API를 부르면 이번 회차 납부 예정이 없는 확정 고정지출의 납부 예정을 먼저 만든다**(C-15: 다음 주기 것은 그 주기에 홈 · 예산을 처음 열 때 만든다). 같은 회차는 `occurrence_key`(회원 · 회차) UNIQUE로 한 번만 생기므로 여러 번 불러도 결과가 같다. 대상은 계좌 · 결제 수단 모름이고 출금일이 있는 확정 고정지출이다.

**⑤ 예산 영역 (`budget`) · 온보딩 — H-06**

- 오늘 쓸 수 있는 돈 · 남은 생활비 · 사용률 · 여윳돈 · 더 써도 되는 돈(= 남은 생활비 + 여윳돈) · 쿠션 상태는 **이번 명세에서 정하지 않는다.** 추천 예산 금액이나 배분 규칙을 추측해 채우지 않는다.
- 응답에는 자리만 두고 `budget: null`로 준다. 칸 구성 · 계산은 예산 API 명세(ML 후)에서 정하고, 그때 `budget` 객체를 채운다.
- 화면: `budget`이 `null`이면 파란 카드 자리에 **안내 카드**를 보여 준다 — "예산을 만들면 여기에 오늘 쓸 수 있는 돈이 보여요 [예산 만들기]".
- **온보딩을 안 끝낸 회원은 홈을 열지 않는다.** 화면이 로그인 뒤 온보딩 진행 단계를 보고 온보딩 화면으로 보낸다. 이 API는 막지 않는다(온보딩 중에 불러도 위 규칙대로 답함). 온보딩 진행 단계를 어느 API가 주는지는 확인 필요 H-08.

**실패하면**

| 상황 | 상태 | `code` | 화면 안내 |
|---|---|---|---|
| 로그인 안 됨 · 세션 만료 | 403 | `not_authenticated` | 로그인 화면으로 ([API_RULES](../API_RULES.md#에러-응답--항상-이-모양): 세션 로그인은 401이 아니라 403) |
| 서버 오류 | 500 | 공통 | "잠시 후 다시 시도해 주세요." + 다시 불러오기 |

- 보내는 값이 없으므로 `400`은 없다.
- 계좌 조회가 일부 실패해도 **오류로 답하지 않는다.** 마지막으로 받은 잔액과 기준 시각, `unknownCount` · `reloginCount`로 상태를 알려 준다(UI-002: 일부 조회 실패는 마지막 값 + 갱신 실패 표시).
- 급여일 미입력 · 계좌 없음 · 납부 예정 없음 · 월급 못 찾음도 오류가 아니라 `null` · `0` · `[]` · `salaryState`로 준다.

### 화면 연결 메모

지금 `HomePage.jsx`는 가짜 응답 모양(`period.label` · `home.balanceTotal` · `home.daily` …)을 읽는다. 이 명세로 바꿀 때 화면도 같이 바꾼다.

| 지금 화면이 읽는 것 | 이 명세 |
|---|---|
| `period.label` "10.01 — 10.31" · `period.dday` · `period.updated` | `period.startDate` · `endDate` · `dday` / 기준 시각은 `balance.asOf` |
| (없음) | `period.salaryState` — `waiting`이면 "월급이 아직 안 들어왔어요" / `period.nextSalaryEarlyOn`이 있으면 "월급이 12/18에 미리 들어왔어요. 12/25부터 예산에 넣을게요" |
| `home.balanceTotal` · `home.accountCount` | `balance.total` · `balance.accountCount` |
| `home.pendingCount` | `pendingCount` |
| (없음) | `needsPaydayCount` — "출금일을 확인할 고정지출 N건 ›" 알림 줄 (확인할 거래 줄과 같은 모양) |
| `mustPay[].name · sub · amount · icon · link` | `mustPay[]` — `sub`(예: "10.24 · 국민 급여통장")와 아이콘 · 이동할 화면은 화면이 `type` · `dueDate` · `paymentAccount`로 만든다 |
| (없음) | `mustPay[].paymentState` — 출금일이 지난 `unpaid`는 "출금 확인 중", `needs_review`는 **"미납 확인 필요 ›"** 배지 + 누르면 고정지출 화면 |
| `home.daily` · `livingLeft` · `livingPct` · `livingBudget` · `spare` | `budget` (ML 후) — `null`이면 파란 카드 대신 안내 카드 |
