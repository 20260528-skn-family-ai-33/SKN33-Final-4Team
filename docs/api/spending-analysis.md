# 소비 분석 카드 명세 — 챗봇 통합 전달안

> 담당: 권세진 · 작성일: 2026-10-21 · 수정일: 2026-10-22 · 명세 상태: 검토용 초안
> 개발 상태: 챗봇 통합 전 전달안 / 소비 분석 카드 계약은 제안·미정 포함, 별도 조회 API 신설 없음
> 기준: [공통 규칙](../API_RULES.md), [결정 기록](../결정기록_2026-10-21.md), [API 목록](../머니쿠션_API_명세_목록_2026-10-21.md), [작성 틀](./_TEMPLATE.md)
> 관련 문서: [인증·회원](./auth.md) · [카드](./cards.md) · [대출](./loans.md) · [소비 분석](./spending-analysis.md)

혜리가 `chat.md`에 통합할 소비 분석 카드 항목·계산 의미·예시를 정리한다. 챗봇 외곽 응답과 `chat.md` 최종 편집은 혜리 담당이며, 팀 합의가 필요한 항목은 미정으로 유지한다. 팀원과 논의할 내용은 이 문서 마지막의 **확인 필요 사항 모음**에서 확인한다.

기존 검토 내용과 참조를 유지하기 위해 API 번호 1~10과 소비 분석 A-1~A-7 번호를 그대로 사용한다. 다른 기능의 번호는 위 관련 문서에서 확인한다.

문서 작성 완료와 팀 합의·구현 완료는 다르다. 본문의 **초안 제안·미정·확정 보류** 표시는 유지했다. 기존 모델에 칸이 있다는 사실만으로 CODEF 제공 여부나 사용자 수정 권한이 확정되는 것은 아니다. 예시의 개인정보·금액·UUID는 모두 가상 값이다.

| 번호 | 기능 | 방식·주소 | 목록의 작성 상태 |
|---|---|---|---|
| 부록 A | 소비 분석 카드 항목·예시 | 챗봇 응답에 포함, 별도 API 신설 없음 | 기본만 |

비밀번호 재설정·ML 입력 정보·추천 예산·쿠션 배분 규칙·후속 차수 기능은 이번에 정하지 않는다. 로그인·내 계정 응답의 `onboardingCompleted`는 첫 예산 승인 시 true이며, false면 저장된 값을 채운 온보딩 첫 단계로 이동한다(결정기록 3-3 R). 1차에는 단계 번호를 반환하지 않는다. 금융 동의·계좌·연결 해제·재조회·챗봇 전체 계약은 혜리 담당이며, `chat.md` 최종 편집도 혜리가 한다.

### 요청·오류·재시도 공통 적용

- 보내는 값 표에 없는 필드와 서버가 정하는 필드(예: `status`)를 보내면 400 `invalid`, 해당 필드에 “이 칸은 보낼 수 없어요.”를 반환한다. 조용히 무시하지 않는다. 아직 확정 보류인 요청 필드는 허용 목록으로 취급하지 않는다.
- 오류에는 `code`·`message`가 항상 있다. `fields`는 입력 칸 오류가 있을 때만 넣고, 로그인 불일치·미인증·404처럼 칸과 무관한 오류에서는 키 자체를 생략한다. 빈 `{}`를 보내지 않는다. 여러 입력 칸의 조합 오류는 `fields.nonFieldErrors`를 사용한다.
- 주소 ID가 잘못된 UUID이거나, 없거나, 남의 항목이거나, 해당 동작을 할 수 없는 상태이면 JSON 404 `not_found`다. 본문 ID의 형식 오류·없는 항목·남의 항목·선택 불가 항목은 400이며, 여러 개 중 하나라도 잘못되면 전체 저장하지 않는다. 존재·소유·선택 가능 여부를 구분해 노출하지 않는다.
- 이미 요청한 상태라면 같은 작업을 다시 반영하지 않고 성공으로 응답한다. 다만 없는 ID·남의 데이터에는 적용하지 않는다. 대출 보완은 `repaying`만 가능하고 `repaid`는 404다(P). 카드의 원천 상태별 선택 가능 범위는 마지막 확인 목록에 남기며 고정지출 상태 코드를 그대로 가져오지 않는다.
- 새로 만들기·승인 요청에 쓰는 `Idempotency-Key`는 입력 폼·팝업을 열 때, 버튼 하나로 끝나는 동작은 누를 때 만든다. 처리 중 버튼을 잠그고 응답 전 재전송에는 같은 키를 쓰며, 완료 후 버린다.
- 요청 번호 적용 대상에서는 같은 회원·키·내용에 처음 응답을 재사용하고, 기록된 키로 다른 내용을 보내면 409 `idempotency_conflict`다. 실패한 4xx·5xx는 기록하지 않아 수정 후 같은 키로 재시도할 수 있다. 회원가입은 이메일 중복 검사·DB 유일성 제약으로 중복 가입을 막으며 별도 요청 번호를 쓰지 않는다(결정기록 3-3 X). 이 규칙만으로 모든 PUT·PATCH에 필수 헤더를 추가하지 않는다.

회원가입·로그인의 세션·CSRF 계약과 이메일 중복 방지는 [인증·회원 명세](./auth.md)를 참조한다.

계좌·카드 표시와 H-07 연결 상태, 금액·날짜·주기·중복 차감 원칙은 [카드·대출 공통 규칙](./cards.md#카드대출-공통-규칙)을 함께 적용한다. 카드 청구와 소비 분석은 별도 계약이다.

## 부록 A. 혜리 전달용 소비 분석 카드

### A-1. 담당 경계와 확정된 원칙

이 부록은 챗봇 응답의 `messages[].content`에 들어갈 카드 부분의 전달안이다. 1차 카드 칸은 `chat.md`로 통합하고 이 문서의 추가 제안 중 `topSpending`·`comparison`만 반영한다(J). `conversationId`, `route`, `messages` 외곽 구조, 작업 진행 확인 API와 `chat.md` 최종 편집은 혜리가 담당한다. 이 파일 수정으로 `chat.md`의 통합 편집이 완료된 것은 아니다.

- 1차는 챗봇 서버가 소비 집계 함수를 호출한다. 별도 소비 분석 조회 API는 2차 대상이다.
- 문장 요청은 라우터에서 LLM을 1회 사용하여 의도·기간·카테고리 등 슬롯만 해석한다. 추천 버튼은 라우터를 건너뛰어 LLM 0회다. 금액·비율은 서버가 집계하고 안내 문장은 템플릿으로 만든다.
- 1차 범위는 총소비·가장 많이 쓴 곳·카테고리별 금액과 비율·지난달 대비다. `topSpending`·`comparison`의 1차 반영은 J로 정해졌으며, 최다 소비는 카테고리 기준이며 동률은 모두 반환한다. 미분류는 순위에서 제외한다(J·N②).
- 카테고리가 없으면 전체, 있으면 해당 카테고리, 비교 기준이 있으면 비교를 추가한다. 기간이 없으면 **이번 달 1일~오늘(달력월)**, 비교 기준의 기본은 지난달이다(결정기록 3-3 A).
- 일반 비율은 0~100 범위의 숫자다. 증감률은 예외로 음수·100% 초과가 가능하며, 이전 금액이 0원이면 null이다. 이전 금액이 0원일 때는 증감률 대신 금액 변화만 안내한다.
- 공통 규칙의 대문자 카테고리 코드와 `category`·`categoryName`을 사용한다. 키 이름은 확정 규칙이며 `chat.md`에도 동일하게 반영할 전달 대상이다. 저축·투자·대출 상환·카드값은 카테고리가 아니다. `UNCLASSIFIED`는 분류 전 상태이며 사용자가 분류 대상으로 선택하는 카테고리가 아니다. 고정지출로 연결된 소비도 총액·카테고리 합계에 포함한다(S). 기본 이체는 소비에서 제외하되, 사용자가 소비로 전환한 이체는 포함한다(W).
- **이번 달이 끝나지 않았으면 지난달도 같은 날짜까지만 비교한다**(결정기록 3-3 C). 예: 10/1~10/21과 9/1~9/21을 비교하고 문장에는 “9월 같은 기간보다”라고 표시한다. 지난달에 같은 날짜가 없으면 지난달 말일까지 자른다(N①). 예: 2026-03-01~03-31과 2026-02-01~02-28. 진행 중인 달이라는 이유만으로 비교 불가 처리하지 않는다. 홈·예산의 H-01 급여주기와 소비 분석의 달력월은 구분하며, 월급날 미설정·실제 입금일로 소비 분석 기본 기간을 바꾸지 않는다.
- **고정지출은 소비 분석의 `total`·카테고리별 금액에 포함하고, 그중 고정지출 합계를 `fixedAmount`로 따로 표시한다(S).** `fixedAmount`는 총액에 이미 들어 있는 부분 금액이므로 다시 더하지 않는다. 예: 총소비 1,320,000원 중 고정지출 770,000원이면 생활비 소비는 550,000원이다. 예산·홈의 생활비 사용액에서는 고정지출을 계속 제외한다.
- '확인 필요' 금액은 `unclassifiedAmount` 한 줄로 보여주고(N④), `topSpending` 순위에서는 빼며 문장에 “분류된 소비 중”을 쓴다(N②). 0원 기간도 소비 카드와 “이 기간엔 소비가 없어요” 문장을 반환한다(Z).
- 연결 해제 전의 거래는 소비 집계에 계속 포함한다(N⑧). 같은 구매는 한 번만 세고(B), 카드값·대출 상환 출금 자체를 원 구매와 중복 합산하지 않는다.
- 카드값 출금↔청구서 매칭·첫 청구서 선차감(Q), 대출 상환↔대출 매칭·월 상환 추정(P)은 세진 담당이다(T). 거래 수집·같은 구매 연결·후처리 입구는 혜리, 고정지출·저축 후보 감지와 고정지출 납부 매칭은 나은 담당이다.
- 라우터가 해석하지 못하면 되묻기와 추천 버튼을 제공하고, 실패 시 `fallback: true`를 사용한다. 이 처리의 챗봇 외곽 응답 계약은 혜리 담당이다.

### A-2. 카드 항목 전달안 — 1차 통합 범위·2차 확장 구분

> **1차 칸은 chat.md로 합침(topSpending · comparison만 반영). coverage · scope 객체는 2차** (결정기록 3-3 J).

1차의 기본 응답은 [chat.md](./chat.md)를 기준으로 합치며, 위의 “만 반영”은 이 문서의 **추가 제안 중** 두 항목을 반영한다는 뜻이다. `chat.md`의 문자열 `scope`(`all`·`category`)와 아래의 계좌·카드 목록을 담는 **객체형 `scope`는 다른 구조**다. 1차에서 객체로 바꾸지 않는다. 실제 통합 편집은 혜리 담당이다. 이름은 `previousTotal`·`categories[].previousAmount`로 확정됐으며, 1차 `comparison.reason`은 `not_requested`·`previous_incomplete` 두 개만 사용한다(J).

**1차 확정 칸 보충 — J·N·S**

기존 `chat.md` 카드 구조에 아래 기준을 적용한다. S의 `fixedAmount`는 J 이후 추가 결정이며, 이 문서에서 혜리에게 전달하는 통합 항목이다.

| 이름 | 타입 | 1차 확정 의미 |
|---|---|---|
| `scope` | 문자열 | `all` 또는 `category`. 객체로 변경하지 않음(J) |
| `total` | 정수 | 전체 소비액(원), 고정지출 포함(S). 특정 카테고리 질문도 전체 기준 |
| `fixedAmount` | 정수 | `total`에 포함된 고정지출 합계(원). 특정 카테고리 질문도 전체 기준, 확인된 고정지출 없으면 0(S) |
| `previousTotal` | 정수 또는 null | 비교 기간 전체 소비액. 비교 불가이면 null(J) |
| `categories[].previousAmount` | 정수 또는 null | 해당 카테고리의 비교 기간 소비액. 비교 불가이면 null(J) |
| `topSpending` | 객체 또는 null | `{ "basis": "category", "items": [...] }`. 분류된 카테고리 중 최고 금액, 동률 모두. 특정 카테고리 질문·0원·분류된 소비가 없으면 null(J·N②) |
| `comparison` | 객체 | `{ "available": true, "reason": null }` 또는 비교 불가 사유(J) |
| `comparison.reason` | 문자열 또는 null | 비교 요청 없음 `not_requested`, 이전 자료 부족 `previous_incomplete`. 비교 가능하면 null. 1차에 `partial_period` 등 다른 코드 없음(J) |

비교 불가이면 `previousTotal`·`categories[].previousAmount`·전체 및 카테고리별 증감액·증감률은 모두 null이다. 고정지출을 포함한 카테고리 비율도 전체 `total`이 분모다. `fixedAmount`를 별도 카테고리처럼 더하지 않는다. 현재 분석의 `period`와 비교 `compare`는 C·N① 기준을 따른다.

**고정지출 표시 예시(S), 변경 필드 발췌**

```json
{
  "kind": "spending",
  "scope": "all",
  "total": 1320000,
  "fixedAmount": 770000,
  "lines": ["이번 달 132만 원 썼어요. 월세 같은 고정지출 77만 원을 빼면 생활비는 55만 원이에요."]
}
```

아래 표와 A-3~A-7은 CHT-006·RPT-001의 집계 근거·수집 공백까지 포함한 **확장 제안의 참고 자료**다. 표 전체를 1차 응답으로 구현하지 않는다. `coverage`·객체형 `scope`는 2차 검토 대상이며, 나머지 추가 필드·상태 코드·계산 세부 규칙도 채택 전 제안으로 유지한다. 기간은 A·C의 달력월·동일 날짜 비교 기준을 따른다.

**최다 소비·숫자 표시 제안**

- “가장 많이 쓴 곳”은 **가장 많이 쓴 카테고리**로 확정됐다(J). 가맹점 순위는 1차 계약에 추가하지 않는다. `topSpending.basis`를 두어 화면이 가맹점 이름으로 오해하지 않게 한다.
- 전체 질문이고 현재 수집이 `complete`이며 분류된 양수 소비가 있을 때만 최다 항목을 반환한다. 동률은 모두 담고 공통 카테고리 표 순서로 정렬한다. 특정 카테고리 질문·부분 수집·0원·전액 미분류이면 null이다. 미분류는 순위에서 빼고 문장에 “분류된 소비 중”이라고 안내한다(N②).
- 비율·증감률은 소수 둘째 자리까지 반올림하는 제안이다. 비율 합계를 억지로 100에 맞추지 않는다. 이전 금액이 실제 0원이면 증감액은 계산하되 증감률만 null이다. 자료 부족으로 모르는 금액을 0원으로 넣지 않는다.
- 특정 카테고리 질문도 `total`·전체 증감·`unclassifiedAmount`는 전체 기준이다. 특정 카테고리가 정상 확인된 0원이면 0원 행을 반환하며, 총액이 양수면 비율 0, 총액도 0이면 비율 null로 제안한다.
- 총액의 고정지출 포함과 별도 `fixedAmount` 표시는 S로 확정됐다. 저축·대출 상환·카드 청구 납부를 소비로 합산하지 않으며 카드 원 결제와 납부를 이중 합산하지 않는다(B). 이체는 기본적으로 제외하되 사용자가 소비로 분류한 거래는 포함한다(W). 취소·환불 귀속의 남은 세부 기준은 마지막 목록에서 확인한다. 환불로 순소비가 음수가 되는 기간의 총액·순위·비율 표현은 미정이며, 아래 비음수 예시만으로 정책을 확정하지 않는다.

**수집 범위·비교 제한 제안 — 객체형 scope·coverage는 2차**

- `scope`는 요청 시점의 선택 목록을 고정한 값이며, 현재와 이전 기간을 서로 다른 선택 목록으로 계산해 비교하지 않는다. 이력 부족으로 같은 범위를 확보할 수 없다면 비교를 제한한다. 이 목록은 사용자의 전체 연결 목록이나 거래가 한 건이라도 있는 목록을 뜻하지 않는다.
- `complete`는 거래가 없는 날도 정상 확인된 상태다. `partial`은 전체 범위를 보증하지 못하지만 집계할 자료는 있는 상태이며 `total`을 “확인된 소비 소계”로 표시한다. 일부 계좌만 수집되어 모든 날짜가 공백 구간이어도 `partial`일 수 있다. `unavailable`은 `total`·`unclassifiedAmount`가 null이고 `categories`는 빈 배열이며 “소비 없음”으로 해석하지 않는다.
- **아래는 2차 검토 전용이다. 1차는 J의 두 코드만 쓴다.** 확장 시 비교 불가 사유를 `not_requested` → `scope_mismatch` → `current_incomplete` → `previous_incomplete` → `partial_period` 순서로 반환하는 제안이다. **`partial_period`는 같은 날짜까지 기간을 맞춘 뒤에도 비교 기준을 충족하지 못하는 경우에만 검토하는 사유이며, 이번 달이 아직 끝나지 않았다는 이유로 반환하지 않는다.** 추가 코드의 채택·세부 조건은 2차에서 검토한다. 10/1~10/21과 9/1~9/21의 자료가 같은 범위로 확보되면 `available: true`, `reason: null`이다(C).
- 비교 불가이면 `previousTotal`, 전체·카테고리별 증감, `categories[].previousAmount`를 모두 null로 보낸다. 현재 수집이 완료되어 있으면 현재 금액·비율·최다 소비는 그대로 표시할 수 있다. **진행 중인 이번 달과 지난달 전체를 비교하지 않고 지난달 같은 날짜까지 잘라 비교한다.** 지난달에 같은 날짜가 없으면 지난달 말일까지 사용한다(N①).
- `coveredPeriods`와 `missingPeriods`는 각 요청 기간을 빠짐없이 나눈다. `complete`는 요청 기간 전체가 확인 구간이고 공백은 빈 배열이다. `unavailable`은 확인 구간이 빈 배열이고 요청 기간 전체가 공백이다. 계좌·카드별 공백을 화면에서 펼치는 추가 구조는 이번 제안에 포함하지 않는다.
- `updatedAt`은 집계에 반영된 원천들의 마지막 정상 조회 시각 중 가장 오래된 값을 사용하는 제안이다. 한 원천의 최신 시각으로 전체가 최신인 것처럼 보이지 않게 한다. 일부 원천의 시각 근거가 없으면 null로 두며 공백은 별도로 안내한다. 기준 시각 원천·오래된 자료 표시 기준은 혜리와 확정한다.
- 집계 실패·동의 미완료는 위 0원 성공 응답으로 대신하지 않는다. 월급날 미설정은 소비 분석의 기본 달력월 기간을 정하지 못하는 사유가 아니다. 실패의 HTTP·챗봇 외곽 응답·재시도 계약은 금융 공통 및 혜리의 `chat.md`에서 별도 합의한다.

**진행 중인 달의 비교 예시(C)**: 기준일이 2026-10-21이면 아래 기간을 비교한다. 두 기간의 자료가 확보된 경우를 설명하는 발췌이며 완전한 1차 응답 예시는 아니다.

```json
{
  "period": { "from": "2026-10-01", "to": "2026-10-21" },
  "compare": { "from": "2026-09-01", "to": "2026-09-21" },
  "comparison": { "available": true, "reason": null }
}
```

안내 문장은 “9월 같은 기간보다 식비가 …”처럼 비교 기준을 밝힌다.

아래 A-3~A-7은 사용자가 **이미 끝난 달을 지정한 가상 데이터**로, 객체형 `scope`·`coverage`를 포함한 **2차 확장 검토용 예시**다. 1차 구현용 응답 복사본이 아니며, 기본 기간은 A-1의 이번 달 1일~오늘이다.

카테고리 하나만 보여도 `total`·전체 증감은 전체 기준이다. 식비 증감률 null과 전체 증감률 33.33%가 함께 있어도 모순이 아니다.

## 구현 전 검토·검증 목록

향후 구현 시 검증할 항목이며 현재 테스트 통과 기록이 아니다.

- [ ] 빈 목록·null·0원·조회 실패를 구분한다.
- [ ] 계좌·카드의 표시 객체와 마스킹, 대문자 카테고리 코드를 지킨다.
- [ ] H-07에 따라 계좌·카드 `status`가 연결된 `connection.status`와 일치하고 별도 매핑·독립 상태 저장을 하지 않는다. 연결 FK 없음 처리는 합의 후 검증한다.
- [ ] 1차 응답은 `chat.md`에 통합하고 기존 추가 제안은 `topSpending`·`comparison`을 반영하고(J), 고정지출 합계 `fixedAmount`를 더한다(S). 객체형 `scope`·`coverage`를 1차에 넣지 않는다(J).
- [ ] J·N의 확정 구조로 최다 카테고리·동률·미분류·전체 증감·특정 카테고리 증감을 검산하고, 부분 수집·이전 자료 없음·범위 불일치를 0원이나 정상 비교로 표시하지 않는다.
- [ ] 기본 기간 이번 달 1일~오늘, 지난달 같은 날짜까지 비교(C), 없는 날짜는 지난달 말일(N①)을 검증한다. 1차 비교 불가 코드는 J의 두 개만 사용한다.
- [ ] 미분류를 최다 소비에서 제외하고 “분류된 소비 중”이라고 안내한다(N②).
- [ ] 총액·카테고리에 고정지출을 포함하되 `fixedAmount`는 부분 금액으로 따로 표시하고 중복 합산하지 않는다(S).
- [ ] 소비가 없는 기간은 0원 카드와 “이 기간엔 소비가 없어요”를 반환한다(Z).
- [ ] 2차 확장 시 소비 수집 구간과 공백이 요청 기간을 빠짐없이 나누고, 집계 대상 계좌·카드·기준 시각이 표시 숫자의 실제 근거와 일치한다.
- [ ] 카드 청구·대출 상환·고정지출·거래를 중복 차감하지 않는다.
- [ ] 소비 카드의 전체·특정 카테고리·비교 없음·비교 0원·음수 증감·100% 초과 증감을 확인한다.
- [ ] 서버가 계산한 금액과 템플릿 문장이 일치한다.
- [ ] 고정지출과 연결된 카드 거래는 생활비 사용액에서 제외하고, 대출 상환 출금은 고정지출 후보로 중복 생성하지 않는다.
- [ ] 홈·예산의 급여주기와 소비 분석의 달력월을 구분하며, 월급날 미설정이나 조기·지연 입금으로 소비 분석 기본 기간이 바뀌지 않는다.
