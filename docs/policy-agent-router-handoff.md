# 청년 정책 추천 에이전트 — 라우터 연결 안내

기준일: 2026-11-03 · 현재 저장소 코드 기준 · 청년 정책 담당자 공유용

**정책 추천 내부 구현은 자유롭게 설계하고, 라우터와 만나는 입력·출력만 아래 형식으로 연결한다.** LangChain·LangGraph 사용 여부는 달라도 된다. 현재 정책 담당은 `not_ready("policy")` 대역이며, 실제 추천 로직은 아직 연결되지 않았다. 아래 미정 항목까지 구현 완료된 계약으로 해석하지 않는다.

이 안내는 `CHAT_ENGINE="router"`인 새 채팅 엔진 기준이다. 기존 `legacy` 엔진과 구분한다.

## 1. 연결 위치와 담당 범위

현재 연결 지점은 `backend/chat/engine.py`의 `answer()` 안에 있는 `agents["policy"]`다. 라우터는 **동기 함수 `handler(request) → dict`**를 호출한다. HTTP API를 새로 만드는 것이 필수는 아니며, 비동기 코드·별도 서버를 쓰면 연결 어댑터를 협의한다.

| 담당 | 책임 |
| --- | --- |
| 라우터·채팅 담당 | 담당 선택·전환, 요청 전달, 채팅 메시지·공유 대화 상태 저장, 응답을 화면 형식으로 변환 |
| 정책 추천 담당 | 조건 해석, 부족한 조건 질문, 정책 검색·추천·출처 설명, 정책 내부 진행 상태, 자기 담당이 아닌 질문 판별 |

정책 조건을 묻는 동안 다음 사용자 문장은 정책 담당에게 먼저 전달된다. 라우터가 매번 분야를 다시 분류하지 않으므로, “이번 달 얼마 썼어?” 같은 다른 분야 질문에는 정책 담당이 `not_mine`을 반환해야 한다.

## 2. 받는 입력 — 현재 구현

다음은 정책 기능 버튼을 처음 누른 경우의 예시다. 날짜는 예시이며 실제로 전달된 기준값을 사용한다.

```json
{
  "agent": "policy",
  "mode": "start",
  "entry": "button",
  "text": null,
  "work_ref": null,
  "input_id": "example-input-001",
  "conversation_id": "conversation",
  "today": "2026-11-03",
  "as_of": "2026-11-03T10:00:00+09:00",
  "context": {
    "conversation_id": "conversation",
    "switched_from": null,
    "declined_by": null
  }
}
```

| 필드 | 정책 담당이 알아야 할 의미 |
| --- | --- |
| `agent` | 정책 담당 식별자: `"policy"` |
| `mode` | `start`(처음) · `continue`(진행 중) · `resume`(보류된 정책 작업으로 복귀, 11-11). `cancel`이 자동 전달된다고 가정하지 않는다 |
| `entry` | `text` 또는 `button`. 정책 담당 중 기능 버튼을 다시 누르면 `continue` + `button` + `text=null`도 들어온다 |
| `text` | 사용자 문장. 기능 버튼으로 진입하면 `null`일 수 있다 |
| `work_ref` | 정책 담당이 이전에 반환한 작업 참조. 없으면 `null` |
| `input_id` | 한 입력의 내부 식별자. 같은 입력의 재전달에서도 유지되지만, 외부 작업의 중복 방지 전체를 보장하지는 않는다 |
| `conversation_id` | **현재 채팅 어댑터 안에서는 고정값 `"conversation"`**. 실제 채팅 DB UUID가 아니다 |
| `today`, `as_of` | 기준 날짜·조회 시각. 더미 환경은 고정 날짜일 수 있고, 독립 테스트에서는 `null` 가능 |
| `context` | 최소 전달 맥락. `declined_by`는 앞서 담당을 거절한 에이전트 또는 `null`. 현재 정책 입력의 `switched_from`은 기본 `null`이므로 전환 이력으로 의존하지 않는다 |

**사용자 객체·프로필·전체 대화 기록은 이 입력에 자동 포함되지 않는다.** 필요한 나이·지역·취업 상태 등은 정책 담당이 목록을 제시하고, 서버에서 조회할 값과 사용자에게 물을 값을 함께 정한다. 인증된 `user`, `store`, LLM 호출기는 소비 분석처럼 `partial()` 등으로 주입할 수 있으나, 정책 연결 시 추가할 사항이다.

## 3. 돌려주는 결과

최소 필수 필드는 `status`다. 사용자에게 보여 줄 내용은 `reply`에 넣는다. 아래는 지역을 추가로 묻는 예시다.

```json
{
  "status": "awaiting_input",
  "work_ref": null,
  "reply": {
    "lines": ["거주 지역을 알려 주세요."],
    "choices": [],
    "notices": []
  }
}
```

| `status` | 사용 상황 | 현재 라우터 동작 |
| --- | --- | --- |
| `awaiting_input` | 지역·나이 등 추가 조건이 필요함 | 정책 담당 유지. 다음 문장을 정책으로 전달 |
| `replied` | 이번 답변을 제공하고 후속 질문도 이어받음 | 정책 담당·작업 유지 |
| `ended` | 추천 대화를 끝냄 | 라우터의 정책 작업 참조 해제. 다음 문장은 다시 분류 |
| `unsupported` | 정책 분야지만 현재 지원하지 않는 요청 | 자동 재분류·종료하지 않음. `reply.lines`에 한계 안내 필요 |
| `failed` | 검색 API·LLM 등 처리 오류 | 공유 store를 이번 입력 전 상태로 복구. `error`에 내부 오류 코드 사용 가능 |
| `not_mine` | 소비 분석·예산 조정 등 다른 담당의 요청 | 재분류 또는 목적지 확인. 정책 상태를 변경하지 않고 반환 |

- **추천 결과가 없음은 정상 검색 결과**다. `failed`나 `not_mine` 대신 `replied` 또는 `ended`로 안내한다. 후속 대화를 받을지에 따라 선택한다.
- 추천 후 “다른 정책도 있어?”를 이어받으려면 `replied`, 대화를 명시적으로 닫으려면 `ended`를 쓴다. 기본 종료 정책은 함께 결정한다.
- `work_ref`는 선택 사항이다. 외부 작업·그래프 실행을 참조한다면 안정적인 식별자를 반환한다. 현재 라우터는 이후 `null`을 반환해도 기존 참조를 유지하며, `ended`에서 해제한다.
- 예외 발생·알 수 없는 `status`는 라우터가 `failed`로 처리한다. 지원되지 않는 상태 이름(`success`, `done` 등)을 그대로 반환하지 않는다.
- 소비 분석 전용 `detail`·`decision`은 복사하지 않는다. 정책은 우선 `status`, `work_ref`, `reply`, 필요 시 `error`로 연결한다.

### 화면에 표시할 내용

`reply.lines`는 문자열 배열이다. `reply.notices`는 안내 배열, `reply.choices`는 `{"value": "seoul", "label": "서울"}` 같은 선택지 배열이다. 선택지는 최신 답변의 버튼만 허용하며, 현재 어댑터는 선택한 **`label`을 다음 요청의 `text`로 전달**한다. `value`가 정책 함수에 직접 들어온다고 가정하지 않는다. `spending`·`budget`·`policy`는 기능 전환 예약값이므로 지역 등 일반 선택지 값으로 쓰지 않는다.

현재 `_content()`가 임의의 `policies`·`sources` 필드를 자동 전달하지는 않는다. 1차 연결에서는 추천명·이유·조건·출처 URL을 `lines`에 담을 수 있지만, 링크 클릭·전용 정책 카드 표시는 별도 화면 협의가 필요하다. `content.result`도 현재 소비 분석 전용 판정이므로 정책 결과 표시를 확장할 때 채팅 담당이 수정해야 한다. HTTP 응답의 camelCase 변환은 서버가 담당하며, 내부 함수는 위 snake_case 형식을 쓴다.

## 4. 상태 저장과 아직 합의할 부분

정책 내부 조건·질문 상태를 공용 store에 저장하려면 `get_agent_state(cid, "policy")` / `save_agent_state(cid, "policy", state)`를 사용한다. 저장값은 JSON으로 직렬화 가능해야 한다. 라우터의 담당·작업 참조 칸은 직접 수정하지 않는다. `ended`는 정책 내부 상태까지 자동 삭제하지 않으므로 자체 정리·보존 기준을 정한다.

LangGraph 등 별도 저장소를 쓸 때 **`request["conversation_id"]`를 그대로 전역 `thread_id`로 쓰면 안 된다.** 현재 고정 문자열이므로 대화가 섞일 수 있다. 실제 사용자·대화와 연결된 고유 식별자를 주입하거나 작업 ID를 발급하는 방식은 채팅 담당과 합의한다. 공용 store 복구는 별도 DB·그래프 저장·외부 실행까지 되돌려 주지는 않는다.

| 통합 전 결정할 항목 | 현재 상태 / 결정할 내용 |
| --- | --- |
| 다른 담당으로 갔다가 정책으로 복귀 | 보류된 정책 작업이 있으면 묻지 않고 `mode="resume"`으로 이어서 전달 (예산 조정 재개와 같은 규칙, 11-11 PR 97 리뷰). 새로 찾기는 정책 에이전트의 [다른 분야 찾기] · [지역 바꾸기] |
| “취소·그만·됐어” | 현재 정책 담당에게 `continue` + 원문으로 전달됨. 질문만 취소할지 추천 대화를 종료할지 합의 필요. 확정된 `cancel` 모드가 있는 것으로 가정하지 않음 |
| 사용자 정보 | 필요한 필드·조회 출처·권한·정보가 없을 때 질문 방식을 결정 |
| 추천 뒤 후속 대화 | `replied`로 이어받을지, `ended`로 종료할지 결정 |
| 출력·실행 방식 | 텍스트 우선인지 정책 카드가 필요한지, 동기 함수로 가능한지 결정 |

## 5. 담당자 간 주고받을 최소 자료

정책 담당자는 **필요한 사용자 정보 목록, 추가 질문 예시 1개, 추천 결과 예시 1개, 추천 없음·오류 처리 방식**을 공유한다. 라우터 담당자는 이를 받아 사용자·store 주입과 `agents["policy"]` 연결, 위 미정 흐름을 반영한다. 별도 프레임워크로 구현하더라도 어댑터 바깥의 형식만 맞추면 된다.

통합 확인 범위: 버튼 진입(`text=null`), 문장 진입, 추가 질문에 답하기, 추천 없음, 다른 분야로 전환(`not_mine`), 오류 시 상태 보존, 취소, 보류 후 복귀. 취소·복귀는 합의한 동작으로 구현한 뒤 확인한다.

참고 코드: `backend/chat/router_core/__init__.py` (`_policy`, `run_turn`, `_record_policy`), `backend/chat/engine.py` (`answer`, `_content`, `_picked`), `backend/chat/router_core/messages.py` (`render`), `backend/spending_analysis/agent.py` (`handle`). 외부 채팅 API는 `docs/api/chat.md` 참고.

이 문서는 연결 안내이며, 정책 에이전트 구현·등록이나 미정 동작을 변경하지 않았다.
