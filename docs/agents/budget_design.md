### 카테고리별 예산 설명 (2026-11-03)
- 화면용 기본은 `explanations`이며 기존 `reasons`는 호환용으로 유지한다. A 후보·규칙 선택·LLM 도구 재계산·실패 대체안과 B 순위 감액 결과가 같은 서버 템플릿을 쓴다. 로컬 계산 창도 최종 선택안의 explanations를 표시한다. API·DB·프론트는 변경하지 않았다.
- 필드: category, reference_type, reference_amount, final_amount, diff, causes[{code, amount, detail}], text. A는 반올림 전 ML 비율 몫, B는 3개월 평균을 기준으로 한다. 카테고리마다 `sum(causes.amount) == diff == final_amount-reference_amount`를 정확히 검사하고 불일치하면 EngineCheckFailed. 원인 금액은 부호 있는 증감액이다.
- A는 기존 배분 루프의 중간값을 읽어 최소·하한·잠금·제외·R-05 내림/자투리를 기록한다. 배분·이동 수식은 변경하지 않았다. 사용자 결정으로 `constraint_redistribution` 코드를 추가했고, 다른 항목의 설정 때문에 재배분된 금액과 원인 항목·조건을 detail에 둔다. 이를 rounding이나 system_floor_raise로 뭉뚱그리지 않는다.
- B는 평균→최소·잠금 반영→천 원 반올림→그룹별 감액→자투리 정산을 기록한다. 하한·최소·되돌리기 보호로 줄어든 감액 가능액은 amount=0인 보조 원인으로 기록하며 가상의 증액으로 더하지 않는다. cut_limit_reached는 뒤 그룹에 실제 부족액이 넘어갈 때 기록한다.
- 최신 사용자 정정: 사용자 요구를 충돌 때문에 충분히 반영하지 못한 경우에만 text를 표시한다. 상위 순위 감액, 더 높은 순위와의 재원 충돌, 재원 부족·전체 이동 한도로 우선순위 증액을 끝내지 못한 경우를 안내한다. 정상적인 하한 적용·최소액 충족·잠금 유지·일반 감액·ML 대비 변동·반올림은 text를 비운다. ML/평균 대비 증감 표시는 문장에서 제거하고 reference/diff/causes는 검증용으로 유지한다. 서버가 정한 증액 목표를 사용자의 희망 금액처럼 표현하지 않는다. LLM이 keep/finish한 것만으로 충돌을 만들지 않는다. 최소액·잠금의 실제 충돌은 기존 infeasible 결과로 반환하며 임의 위반 예산을 만들지 않는다. 최소액 사유 원문은 설명·로그·외부 호출에 복사하지 않는다.
- 비정수 ML 몫·3개월 평균은 내부 `Fraction`으로 보존한다(합계 검사에 float 허용오차를 쓰지 않음). A 안내는 ML 대비 차이를 표시하지 않고, 충돌을 일으킨 조건별 재배분액과 최종 배정액을 표시한다. B 충돌 안내에는 지난 3개월 평균 대비 최종 차이를 표시하며 비정수 차이는 약 표기한다. 향후 API 직렬화에서는 분자/분모 등 정확한 전달 형식을 합의해야 한다. 설명은 LLM 입력으로 보내지 않으며 기존 도구 입력·출력의 금액 필드만 전달한다.
- ML 호출을 생략하는 0원·전체 잠금 경로에서는 새 예측을 만들지 않는다. 제공된 유효 비율이 없으면 설명 원장은 0에서 시작하고 `detail.reference_unavailable=True`, text는 비워 둔다. 이는 실제 ML 예측 0원을 뜻하지 않는다. A에 과거 이력이 없으므로 ml_base_ratio 원인 코드는 생성하지 않는다.
