Tkinter 창에서 원 단위 초안·순위·최소·잠금·실험 한도·경고선을 입력해 실제 build_candidates를 호출. 초안 합계는 기타 제외 배분액과 같아야 하며 입력 초안/기본안/개인화안/이동 내역/종료 사유를 표시. 직접 입력 모드는 ML을 호출하지 않으며, 별도 ML 버튼은 로컬 실제 모델을 사용. 외부 LLM·DB 조회/저장·결과 파일 저장 없음.
- 직접 입력 도구 검증: `local_workspace/tests/test_budget_design_simulator.py`는 혜리 PC 전용. 초기 숫자는 테스트 예시이며 서비스 기본값이 아님. 3단계 추가 테스트를 포함해 15개 모두 통과(실제 모델 버튼→후보 표 표시, 정밀도, 오류/30초 제한, 입력 변경 결과 폐기, 0원/충돌/전체잠금 호출 생략). 팀 계산 테스트의 최신 실행 결과는 아래에 별도 기록.

- 새 `budgets.design_candidates.ml_profile`: 팀 결정대로 take_home_income→disposable_income, housing_fixed→fixed_expense_amount, target→living_budget_amount. male/female→0/1, bool 차량→0/1. 원 단위 그대로, 고정비 재차감·천원 변환·분기 나누기 없음.
- 새 `build_candidates(inp, ratios, policy=None, warning_thresholds=None)`: 기존 R-05 하한/잠금/만원 내림에 ML 비율을 전달. 모든 후보를 기존 `check_result`로 검수. 정책 미지정 시 기본 후보만 생성. 기존 proposal-v1 고정 비율 분기는 제거.
- 정책은 `total_limit`(총이동 원), `increase_rates`(카테고리별 증액률 %, 20=20%), `increase_limits`(추가 증액 금액 한도 원), `decrease_limits`(누적 감액 원), `ceilings`(추가 증액 중단 상한 원)로 명시. 감액 한도는 10개 전체, 증액률·증액 금액 한도·상한은 활성 비잠금 상위 1~3위에 필수. 음수·bool·누락·비유한 증액률·잘못된 코드는 거부. 기존 API는 변경하지 않음.
- 주거·통신: 기존 낮은 ML 예측(저장 결과 중앙값 약 1,525원)과 만 원 내림을 고려한 비활성 규칙 유지. 양수 최소 금액 또는 잠금 키가 있으면 활성. 여행은 ML 예측 0원 때문이 아닌 **월 예산 기본 제외 정책**. 여행 최소/잠금 활성 코드는 위 미정 사항에 따라 일단 보존. 비활성 몫은 재배분하며 내부 10개 검수 결과의 0원 키와 `active_categories`를 유지.
- 미입력 → 4위 이하 순서로 재원 검토, 각 그룹 안에서는 활성 선택 지출 우선. 이후 수혜자보다 낮은 1~3위 쇼핑·뷰티·문화만 마지막 재원으로 검토(여행 순위 금지). 상위 여러 항목을 순위대로 증액. 최소 금액·잠금은 항상 보호.
- `transfers`는 개인화 후보의 이동 내역이고 `stop_reasons`는 해당 후보의 한도 도달/재원 소진 기록. 기본 후보가 선택되면 이 이동 내역을 적용하면 안 됨. 이미 받은 증액을 후속 항목 재원으로 재사용하지 않음.
- `warning_thresholds`는 서버가 준비한 쇼핑·뷰티·문화·여행 최소 요청액 참고선. 초과 시 `high_minimum`, 최소가 상한을 넘으면 `minimum_above_ceiling`. 금액 자동 축소 없음. 설정 충돌은 `constraints_conflict` 및 챗봇/설정 검토용 `next_action` 반환, 실제 라우터 호출 없음.
- 개인화 후보의 `reasons`는 `transfers`의 from/to/amount와 수혜자 순위로 서버가 생성하는 문자열 목록. 예: "패션·쇼핑에서 10,000원을 식비 예산으로 옮겼어요(식비 1순위)". LLM 생성 금액 없음. 기본 후보에는 개인화 이동 설명을 넣지 않음. 설명 영속화·API 표시는 미연결.
- 새 `select_candidate`: 기본 동작은 **검수된 priority가 있으면 선택, 없으면 base**인 규칙 선택. `choose` 콜백은 향후 강도가 다른 후보가 생길 때 LLM 재검토용으로 유지. 명시적으로 콜백을 주면 순위·방향·사유 코드만 전달하며 금액/자유 설명 출력 거부. 실패하면 규칙 선택 결과(priority 우선, 없으면 base)로 돌아가고 `fallback="selector_failed:ValueError"`처럼 오류 종류만 남김(메시지·사용자 입력 기록 없음). 단일 후보는 호출 생략.
- 기존 `budgets.recommend.check_inputs/allocation_conflicts/infeasible/check_result`를 수정 없이 사용. 기존 `recommend_category_budgets`, 자물쇠 함수, 라우터·chat·config·API 연결은 변경하지 않음.

## 필요한 것

- 선택 보완: 최소 금액 때문에 ML 초안보다 높아진 기본 후보의 설명은 연결 시 추가 검토. 현재 reasons는 개인화 이동만 설명하며, 최소 금액 보장은 계산·검수에서 이미 수행한다.

- 여행 최소 금액·자물쇠의 허용/그 달 여행 해석 결정 필요. 위 '팀 합의 필요' 참조. 현행 활성 코드를 임의 변경하지 않음.
- `FinancialProfile.monthly_disposable_income`·`disposable_income_basis`가 있음. 값이 있으면 실수령액보다 우선 사용할지 **나은님 확인 필요**. 현재 `ml_profile`의 take_home_income 매핑은 유지. 사용 시 입력 스냅샷·해시 계약도 함께 확인.
- D2 수치 결정: 카테고리/순위별 증액률, 총액/항목별 한도 적용 방식, 카테고리 상한, 감액 한도, 경고 기준 산정. 증액률 20%·총한도 10만원은 테스트 예시이며 서비스 확정값 아님. 최신 사용자 요청에 따라 천 원 단위 반올림은 구현. 사례는 `local_workspace/output/technical_design/budget_design/예산_설계_D2_합성사례.md` 참고.

## 임시 결정

- 3단계 로컬 계산 창: `local_workspace/scripts/budget_design/simulator.py`의 'ML로 예측·계산'이 같은 폴더 `predict_worker.py`를 전용 ML Python으로 실행. 이 파일들은 혜리 PC에만 있음. 프로필은 명령행 인자가 아닌 stdin JSON으로 전달, 모델은 기록된 SHA256 검증 후 로드. 공용 코드·requirements·API·DB 모델 변경 없음.
- 단발 로컬 도구라 버튼마다 모델을 읽는다. 서비스 연결 때는 프로세스별 1회 로드·재사용 검토 필요. subprocess 30초 초과는 종료·오류 표시하며 기본 초안으로 몰래 대체하지 않음. 백그라운드 실행 중 버튼 중복 클릭 제한, 입력 변경 시 결과 폐기. 상세 traceback·입력 로그를 화면/파일에 남기지 않음.
- ML에는 `T=L−O`와 기존 `ml_profile` 매핑을 전달. 최소/잠금 충돌·T=0·10개 전체 잠금이면 ML 호출 생략. 한글 카테고리→코드를 명시 매핑하고 비율·금액 합계/유한값/모델 ID를 검증. 초안을 정수로 반올림해 다시 가중치로 사용하지 않음. 모델 출력은 표시만 소수 둘째 자리, 엔진에는 원 비율 전달.
- 화면의 여행 순위 입력은 제거하고 코드에서도 거절. 여행 최소/잠금 동작은 결정 전 그대로 유지. 이는 개인 테스트 창 변경이며 나은님 담당 서비스 화면/API 변경을 대신하지 않음.

- ML 연결 1단계(2026-10-30): `local_workspace/.venv-budget-inference/Scripts/python.exe`에 Python 3.12.14, numpy 2.5.4, pandas 3.1.0, catboost 1.2.10, joblib 1.6.0을 준비. 기존 `scripts/budget_allocation/requirements-inference.txt`를 그대로 설치하고 `pip check` 통과. 위 SHA256과 모델 ID 일치, 입력 6개·카테고리 10개·대체 비율 구조 검증 및 `load_bundle` 성공. 측정한 로드 0.846초는 라이브러리 import 이후 1회 값이며 서비스 응답 시간 보장이 아님. 예측·금액 계산·LLM·DB 호출은 하지 않았음. 이후 2단계 합성 추론 검증 완료. 이후 3단계 로컬 계산 창의 실제 ML 버튼 연결도 완료. 서비스 API·배포와는 별개.

- 최신 사용자 결정: 뷰티·미용(BEAUTY)도 선택 지출에 포함. 미입력/후순위 그룹 내 감액 우선, 상위 순위에서는 더 높은 순위의 수혜자에 대한 마지막 재원으로만 검토. 최소 금액·잠금은 계속 보호. 같은 선택 지출 그룹 안의 별도 업종 서열은 정하지 않았으므로 기존 코드/순위 동률 처리 유지.

- 직접 입력 도구의 상한 칸은 현행 엔진의 추가 증액 중단 기준이다. 기본 후보 자체가 이미 상한보다 클 때 그 금액을 소급 감액하지 않는다. 최종 예산 전체에 대한 강제 상한 정책은 별도 결정 필요. 도구도 이 차이를 안내한다.

- 1차 검토는 과거 소비 없이 ML+입력으로 진행. 이력 필요성이 확인되면 소비 분석과 같은 최근 완료 달 최대 3개월만 별도 합의.
- D9 입력 매핑은 사용자가 확정한 서비스 근사값이다. 통계의 소득−비소비지출과 실수령액이 정의상 완전히 같다는 주장은 하지 않음.

- 최소 보장액은 기본 후보를 만들 때 먼저 충족하므로 일반 이동 한도의 예외. 상한보다 큰 최소도 총예산 안에서는 보장하며 충돌/경고를 반환. 개인화 종료는 ML 초안×증액률 목표·총한도·항목 한도/상한 도달 또는 재원 소진. 임의의 적정 소비 금액을 추측하지 않음.
- 최신 사용자 결정: 증액 재원을 순위별 비중으로 나누지 않음. 원 ML 초안 금액 × 증액률로 목표를 계산하며 천 원 단위 반올림(500원은 올림, half-up). 최소·잠금·비활성 항목 재배분·만원 내림 이후의 기본 후보 금액을 증액률 기준으로 사용하지 않음. 최소 충족은 여전히 별도 선행 단계. 초안이 0원이면 비율 증액은 0, 최소 보장액은 먼저 충족.
