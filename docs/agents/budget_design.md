## 2026-11-06 서비스 연동 점검 및 잠금 후속 수정

- 역할 정정: 카드 내역 수집·공용 거래 정합성은 나은님, 예산 배분 ML·예산 설계/조정 프론트·서비스 연결은 혜리 담당이다. 세진님에게 예산 ML/카드 수집 확인을 요청하는 것으로 해석하지 않는다. 팀 메시지는 보내지 않았다.

## A·B 개인화 개선 (합성 테스트 단계)

- A는 비교 창의 합성 상황 메모를 신뢰할 수 없는 참고 데이터로 LLM에 전달한다. 실제 사용자 메모 외부 전송은 여전히 허용하지 않는다. 서버가 기존 감액 우선순위를 지키는 범위에서 기본 재원 순서와 같은 미배정 그룹의 여유 금액 우선 순서를 포함한 미리보기를 제시하고, LLM은 금액이 아닌 선택지만 반환한다. 최소액·잠금·하한·전체 한도와 실패 시 기본안은 유지한다.
- B 예측 LLM에는 각 달의 금액·증감·평균·중앙값·최근 증가율, 우선순위와 합성 상황 메모, 선택적인 최소액 사유를 참고값으로 전달한다. 거래 목록이 없으면 구매 건수와 일회성 판정이 불가하다는 사실을 명시한다. 사유는 신뢰할 수 없는 입력이며 결과·오류에 그대로 담지 않는다. 예측 범위는 기존 명시적 설정을 계속 사용하고 서버 검수·실패 대체는 유지한다.
- A/B 자동 선택 기준·공용 API·DB·모델·마이그레이션은 이 개선에서 변경하지 않는다. 실제 LLM이 문맥을 제대로 활용하거나 현실적인 예산을 만든다는 품질은 아직 입증되지 않았다. 합성 사용자로 결과 검토가 필요하며 실제 사용자 외부 전송 동의·API 통합은 별도다.

## 2026-11-05 A 순위별 증액 미리보기 수정

- 기존 A는 1~3순위를 차례로 판단했으나, 목표율 제거 후 한 항목이 전체 한도를 소진하는 회귀가 있었다. 서버가 남은 한도를 남은 활성 우선순위 항목 수로 나눈 몫을 기준으로 작은·중간·큰 안을 만들고 LLM이 하나를 고르거나 유지·종료한다. 이는 카테고리 금액의 고정 비율이 아니라 **후순위 검토 기회를 남기는 임시 선택지 생성 규칙**이며, LLM은 금액을 생성하지 않는다. 남은 한도·재원과 잠금·최소액·하한을 서버가 매번 검수한다.
