## 슬라이드 1. 청년 정책 추천 에이전트

**한 줄**: 사용자가 고민을 말하면, 사는 지역에서 받을 수 있는 청년 정책 3,664건 중 맞는 것을 찾아 알려 준다.

**흐름**
```
고민 문장 → [LLM] 질문 읽기 · 행동 고르기 → 지역 · 마감 거르기 → 벡터 + 키워드 검색
         → 자격 거르기(코드) → [LLM] 돌아보기 → 정책 카드 3개
```

- 벡터 DB: PostgreSQL + pgvector (정책 1건 = 벡터 1개)
- LLM 은 판단만 한다: 무엇을 할지 고르기, 맞는 후보 고르기. 정책명 · 금액 · 기간 · 링크는 DB 값 그대로
- LangChain 체인(`프롬프트 | LLM | 출력 파서`)으로 LLM 을 부른다

## 슬라이드 2. 문제 → 시도 → 고른 이유 → 결과

| 문제 | 시도 | 고른 이유 | 점수로 본 결과 |
|---|---|---|---|
| 문장만으로 찾으면 엉뚱한 정책이 나온다 (저축 질문 → 결혼장려금 · 월세대출) | 벡터 + 키워드 함께 검색, LLM 이 질문에서 키워드를 뽑음 | 벡터는 뜻을, 키워드는 "응시료" 같은 핵심 단어를 잡는다 | 정답 3위 안 **16.7% → 61.1%** (정답 문제 18개) |
| 단어만 겹치는 정책이 섞인다 (자격증 질문에 건설기술인 교육) | LLM 돌아보기: 후보 10개 중 질문 목적에 맞는 것만 남김 | 나이 · 지역은 코드로 거를 수 있지만 "목적에 맞나"는 규칙으로 못 가린다 | 3위 안 정답 **13 → 16 / 10 → 14**, 보인 카드 54 → 44 |
| 다른 지역 정책이 섞인다 (서울 중구에 충청북도 취업박람회) | 검색 전에 지역을 거르고, 문장 속 지역은 LLM 이 읽음 | 후보의 80%가 지역 한정이라, 찾고 나서 거르면 남는 게 거의 없다 | 기대한 지역으로 찾은 비율 **85.1% → 100%** |
| 규칙만으로는 대화를 못 따라간다 ("아까 두 번째 정책", "추천한 거 무조건 받지?") | LLM 이 다음 행동을 고름: 찾기 · 상세 · 다른 담당 · 끝내기 | 같은 문장도 앞 대화에 따라 할 일이 달라진다 | 총점 **52.7 → 78.2**, 맞는 정책 없는 질문 26개 모두 억지 추천 없음 |

## 슬라이드 4. 청년 정책 추천 평가 (표 슬라이드)

**부제**: 질문 327개를 같은 조건으로 돌리고, 더 큰 모델(gpt-6.2-sol)이 4개 기준(추천 적합성 55 · 자격·지역 20 · 사실 정확성 15 · 요청 이해 10)으로 채점했어요.

| 평가 항목 | 검색만 | 고정 흐름 | LLM 에이전트 (현재) |
|---|---|---|---|
| 테스트 질문 수 | 327 | 327 | 327 |
| LLM 채점 총점 (100점) | 53.5 | 52.7 | **78.2** |
| 첫 화면 정답률 | 41.3% | 41.3% | **70.7%** |
| 지역 정확도 | – | 85.1% | **100%** |
| 평균 응답 시간 | 0.3초 | 0.3초 | 9.5초 |
| 오류·실패 건수 | 1 | 0 | **0** |
| 치명적 오류 (채점자 지적) | 3 | 11 | 3 |
| 비고 | 문장 그대로 검색 상위 3개 | 규칙 + 자격 거르기, LLM 없음 | 읽기 · 행동 고르기 · 돌아보기 · 다시 검색 (LLM 평균 3.6회) |

**해석**
- **결과**: LLM 에이전트가 규칙 방식보다 총점 25.5점, 첫 화면 정답률 29.4%p 높아요. 차이는 대부분 추천 적합성에서 났어요 (평균 2.3 → 3.9점, 5점 만점).
- **잘된 점**: 맞는 정책이 없는 질문 26개에 모두 억지 추천을 하지 않았고, 문장 속 지역을 읽어 기대한 지역으로 100% 찾았어요.
- **개선할 점**: 대화형 질문이 약해요 (사용자 평가셋 65.6점). 이름으로 가리킨 정책("방금 추천한 ○○사업")을 상세로 찾지 못하고, 응답이 평균 9.5초로 느려요.

## 슬라이드 4-1. 한 장 평가 (이미지: `images/policy_eval_slide.png`, 원본 `images/policy_eval_slide.html`)

- 왼쪽 파란 칸: 평가셋 327개 · **78.2점** LLM 채점 총점 · **70.7%** 첫 화면 정답률
- 그래프 "고치기 전과 후 · 총점": 규칙만(LLM 없음) 52.7 → PR 97 74.3 → 베타 피드백 76.3 → 응답 개선 75.1 → 다시 검색 76.5 → 현재 78.2, "LLM 도입 +21.6" 표시
- 아래 칸 3개: 지역 정확도 100% (41/41) · 억지 추천 0건 (정책 없는 질문 26개) · 평균 응답 시간 9.5초 (개선할 점)

**대본 (약 1분 30초)**
> 청년 정책 추천 에이전트는 질문 327개로 평가했습니다. 8개 분야별 시험지 258개, 사용자 프로필을 붙인 평가셋 60개, 개발하면서 실제로 넣어 본 질문 9개입니다.
>
> 채점은 에이전트보다 큰 LLM에게 맡겼습니다. 채점 모델이 정책 DB 원문과 대조해서 네 가지 기준으로 1점에서 5점을 주고, 가중치로 합쳐 100점 만점으로 냈습니다. 가장 중요한 "질문에 맞는 정책을 찾았는가"에 55, 자격과 지역에 20, 정책 정보가 원문과 같은지에 15, 요청을 이해했는지에 10을 줬습니다.
>
> 현재 총점은 78.2점입니다. 첫 화면 정답률은 70.7%로, 정답 정책이 있는 질문 276개 중 195개에서 첫 답의 카드 3개 안에 정답이 나왔습니다.
>
> 그래프는 고치기 전과 후입니다. 맨 왼쪽 회색은 LLM 없이 규칙으로만 찾는 방식인데 52.7점이었습니다. LLM이 질문을 읽고, 할 일을 고르고, 후보를 돌아보게 하면서 74.3점으로 21.6점 올랐습니다. 그 뒤 베타 피드백, 응답 개선, 다시 검색을 거쳐 현재 78.2점입니다. 버전마다 질문을 한 번씩 돌린 결과라 1~2점 오르내림은 LLM 변동일 수 있고, 전체 흐름은 꾸준히 올랐습니다.
>
> 아래를 보시면, 지역이 정해진 질문 41개는 모두 기대한 지역으로 찾았고, 맞는 정책이 없는 질문 26개에는 억지로 추천하지 않았습니다.
>
> 채점을 믿을 수 있는지 사람이 20건을 직접 매겨 비교했는데, 채점 모델이 조금 더 엄격했지만 대체로 비슷했습니다.
>
> 아쉬운 점은 응답 시간이 평균 9.5초로 느리다는 것과, "방금 추천한 정책 자세히"처럼 앞 대화를 가리키는 질문에 약하다는 점입니다. 다음으로 이 두 가지를 개선하겠습니다.

**질문 받으면 (참고)**
- 정답률 분모가 276인 이유: 정답이 따로 없는 대화형 질문 51개는 정답률에서 빼고 채점 점수에만 넣음
- 규칙만 방식의 첫 화면 정답률은 41.3% (114/276), 억지 추천 26개 중 26개
- 정답률은 다시 검색(11-16) 72.1%가 가장 높고 현재 70.7%

## 슬라이드 7. 채점을 믿을 수 있나

- **사람 검수 20건**: 채점자가 사람보다 엄격했어요. DB 에서 확인되지 않는 자격(가구소득 · 국적 등)을 안내하지 않았다고 감점하기도 했지만, 대체로 사람 점수와 크게 다르지 않았어요.
- **채점 기준도 데이터로 고쳤어요**
  - 시범 채점 근거를 읽고 4가지 오판을 고침 (정상 링크 감점 · 정답 해석 · 빈 답 만점 · 허용된 지역 확인 감점)
  - '안내 명확성'은 고정 문구 유무만 재서 총점에서 뺐고, 핵심인 추천 적합성 가중치를 30 → 55로 올림
- **한계**: 질문마다 1회 실행 · 채점자도 LLM · 정답은 사람이 고름
