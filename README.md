# 머니쿠션 (Money Cushion)

> 사회초년생 청년을 위한 멀티에이전트 기반 AI 금융 웰니스 서비스
> SK네트웍스 Family AI 캠프 33기 · 4팀

첫 월급을 받은 사회초년생이 **월급을 어떻게 나눌지**, **다음 월급날까지 얼마를 더 써도 되는지**, **예산을 어디서 어떻게 바꿀지**를 함께 판단해 주는 AI 금융 코치입니다.

| 항목 | 내용 |
|---|---|
| 대상 | 첫 소득과 독립적인 금융생활을 시작한 사회초년생 (매월 급여를 받는 사용자) |
| 이용 조건 | 본인 은행 계좌 1개 이상 연결 필수 (CODEF) · 카드 · 대출 조회는 선택 · **조회 전용** (송금 · 결제 · 가입 · 대출 실행 없음) |
| 제공 형태 | 모바일 웹: React 화면 + Django API (네이티브 앱은 후속) |
| 기간 · 인원 | 2026. 9. 28. ~ 11. 20. (8주) · 3명 |

## 핵심 개념

| 용어 | 의미 |
|---|---|
| **안전 소비액** (더 써도 되는 돈) | 다음 급여일까지 **남은 생활비 + 여윳돈**. 고정지출 · 저축 · 쿠션은 별도 예산이라 다시 빼지 않음. 부족하면 부족액으로 표시 |
| **여윳돈** | 아직 어느 예산에도 배정되지 않은 돈 |
| **일일 권장액** (하루 생활비) | 남은 생활비 ÷ 다음 급여일까지 남은 날 |
| **머니 쿠션** | 돌발 지출 외에는 손대지 않는 최소 안전선 (목표: 월급의 3배). 입출금 잔액이 목표 이상이면 설정 여부 선택, 미만이면 매달 먼저 배정 |
| **보호 조건** | 저축 · 쿠션 하한(지킬 돈)처럼 어떤 조정안에서도 깨지면 안 되는 조건 |
| **자물쇠** | 사용자가 고정한 카테고리. 에이전트가 금액을 바꾸지 않음. 주거/통신 · 교통 외 카테고리 자물쇠를 한 주기에 3회 이상 바꾸면 잔소리 문구 표시 |
| **사용자 승인** | AI는 제안만 하고, 계산 엔진 검수를 통과한 안을 사용자가 승인해야 새 예산 버전으로 저장 |

## 기능과 구현 범위

| 단계 | 기능 |
|---|---|
| **1차 (MVP)** | 회원 · 계좌 연결 · 예산 설계 (추천 예산 1개 · 자물쇠 · 챗봇으로 초안 수정) · 거래 자동 분류 · 홈 · 더 써도 되는 돈 · 예산 조정 (초안 · 평소) · 통합 챗봇 (소비 분석 = 내 소비 집계 · 예산 조정) · 머니 쿠션 |
| **2차** | 소액 돌발 · 카테고리 초과 감지 → 예산 조정 · 소비 분석 화면 · 예산 변경 이력 · 알림 (지난주 대비 소비) |
| **3차** | 큰 지출 상담 (동의 기반 복지 검색 · 대출 비교) |
| 검증 후 채택 | 카드 OCR |
| 후순위 | 일정 · 예정 지출 (Google Calendar) · 목표 · 청년 정책 추천 · 예적금 · 카드 추천 · 소비 분석 LLM 문장 · 네이티브 앱 |
| 제외 | 공동 결제 정산 · 출금 계좌 잔액 부족 알림 · 구매 상담 |

1차 통합 점검 후 2차 → 3차 순서로 붙입니다. 상세 요구사항은 [`산출물/01_기획/4팀_요구사항정의서.xlsx`](산출물/01_기획/)를 기준으로 합니다.

## 시스템 구성

```mermaid
flowchart LR
    U[모바일 웹 브라우저<br/>React] -- /api JSON --> API[Django 서버<br/>DRF · 세션 로그인]
    API --> R{규칙 라우터}
    R -- 단순 조회 --> E[계산 엔진]
    R -- 판단 필요 --> Q[SQS] --> W[AI Worker<br/>LLM 에이전트]
    W --> E
    W --> ML[ML 모델]
    E --> DB[(PostgreSQL)]
    ML --- S3[(S3)]
    API --> EXT[외부 API<br/>CODEF · 상가정보 · 검색/지도 · 복지]
```

- **규칙 라우터 · 빠른 조회**: 잔액 · 더 써도 되는 돈은 LLM 없이 DB · 계산 엔진으로 즉시 처리. 라우터도 LLM 없이 버튼 · 진입점으로 에이전트와 모드를 정함
- **역할 분리**: LLM은 의도 해석 · 우선순위 판단 · 재분배안 작성 · 설명 / ML은 분류 · 비율 · 또래 소비 예측 / **금액은 계산 엔진만** 계산 · 검수
- **검수 후 승인**: 예산에 영향을 주는 변경은 엔진 검수 통과안만 보여주고 승인 후 반영. 검수 실패 시 재생성 최대 3회, 이후 사용자 확인으로 전환
- **버튼 기반 통합 챗봇**: 첫 화면 자유 입력 없이 선택지 3개 (소비 분석 · 예산 조정 · 큰 지출 상담). 1차는 소비 분석 (내 소비 집계, LLM 미사용) · 예산 조정을 제공하고 큰 지출 상담만 '준비 중'으로 비활성

### 멀티에이전트

| 에이전트 | 하는 일 | 단계 |
|---|---|---|
| 라우터 (규칙) | 버튼 · 진입점으로 담당 에이전트와 모드 지정 | 1차 |
| ① 거래 분류 | ML 1차 분류 → 확신도 낮으면 검색 · 지도 + LLM 판단 → 불명확하면 사용자 확인 | 1차 |
| ② 예산 설계 | 방향별 비율(규칙) → ML 카테고리 비율 → LLM 보정 → 엔진 검증 | 1차 |
| ③ 예산 조정 | 엔진이 조정 가능 금액 계산 → LLM 재분배안 → 엔진 검수 → 사용자 승인. 모드: 초안 조정 · 평소 조정 (1차) / 소액 돌발 · 카테고리 초과 (2차) | 1차 · 2차 |
| ④ 큰 지출 상담 | 부족 금액 계산 → (동의 시) ④-1 복지 검색 · ④-2 대출 비교 → 결과 통합 | 3차 |

> 작업당 LLM 호출 10회 이하 · 재생성 3회 이하. 에이전트는 DB를 직접 변경하지 않습니다.

### ML 모델

| 모델 | 쓰임 | 입력 | 학습 데이터 | 기준선 → 평가 | 단계 |
|---|---|---|---|---|---|
| 거래 분류 (ML-001) | 거래 유형 · 소비 카테고리 | 거래 적요 · 상호명 · 금액 · 시간 | 상가(상권)정보 API · 검증 거래 표본 | 규칙 · 사전 · n-gram → macro-F1 | 1차 |
| 카테고리 비율 예측 (ML-003) | 예산 설계 | 연령대 · 성별 · 자차 보유 여부 · 소득 | MDIS · KOSIS 가계동향조사 | 평균 · 규칙 → MAE · 사용자 수정률 | 1차 |
| 또래 비교 회귀 (ML-004) | 소비 분석 화면 | 연령대 · 자차 보유 여부 · 소득 | MDIS · KOSIS 가계동향조사 | 평균 → R² · 잔차 | 2차 |

### 개발 환경

화면은 **React**(`frontend/`), 데이터와 계산은 **Django API**(`backend/`)가 맡습니다. React가 `/api/...`로 요청하면 Django가 JSON으로 답합니다.

```
React (localhost:5173) ──/api──▶ Vite 프록시 ──▶ Django (127.0.0.1:8000) ──▶ PostgreSQL
```

- 처음 세팅: [`docs/LOCAL_SETUP.md`](docs/LOCAL_SETUP.md) (Windows · macOS 단계별)
- 환경변수 설명: [`docs/ENV_SETUP.md`](docs/ENV_SETUP.md)
- 실행: 터미널 2개 — `backend`에서 `python manage.py runserver`, `frontend`에서 `npm run dev` → http://localhost:5173
- 로컬 DB: Docker로 띄운 PostgreSQL 17
- 화면 코드: `frontend/src/` (`pages/` 화면 · `popups/` 팝업 · `components/` 공통 부품 · `styles/` CSS)
- API 코드: 각 앱의 `api.py`, 주소 목록은 `backend/config/api_urls.py`
- API 값은 DB 연결 전까지 각 앱의 `mock.py` 가짜 데이터를 씁니다. 회원 모델이 나오기 전에는 `makemigrations`를 하지 않습니다.
- `backend/templates/`의 Django 화면은 React 이전이 끝나면 지울 예정입니다 (그 전까지 비교용).

## 데이터 원칙

- 개발 · 시연은 **합성 · 모의 데이터**로 진행하고, 실제 개인정보를 로그 · 데모에 노출하지 않습니다.
- 원본 · AI 후보 · 사용자 확정 값을 분리 저장하고, 계산은 같은 시점 자료의 스냅샷으로 수행합니다.
- 토큰 · 계좌번호는 암호화 · 마스킹하고, 외부 API에는 필요한 최소 조건만 전달합니다.
- API 키 · 원본 데이터는 커밋하지 않습니다.
