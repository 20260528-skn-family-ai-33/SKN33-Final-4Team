이 문서를 어떻게 확인했나요?

현재 main의 전체 이력과 이 컴퓨터에 남은 다른 작업 줄기를 확인했습니다. 작성자 김나은과 naeuneo는 이름이 들어 있는 커밋 제목을 함께 보고 나은 님의 기록으로 묶었습니다. 작성자 표시는 저장 기록의 귀속이며, 모든 줄을 혼자 작성했다거나 전체 기여도를 증명하는 수치는 아닙니다.

GitHub 서버의 최신 기록을 새로 받아오지는 않았습니다. 따라서 범위는 현재 컴퓨터에 있는 저장소 기록입니다. 원격 추적 이름도 이 컴퓨터에 마지막으로 저장된 상태예요. 이번에 커밋되지 않은 과거 작업 시간이나 다른 사람의 컴퓨터에만 있는 변경은 집계에 들어가지 않습니다.

커밋 제목뿐 아니라 변경 파일 목록과 현재 코드를 대조했습니다. 문서에 남은 과거 시험 성공 기록과 이번에 직접 실행해 확인한 결과는 구분했습니다.

06 / 어려운 말 작은 사전

이 문서에 나온 개발 용어

커밋 · Git
커밋은 “이 시점의 변경을 이름 붙여 저장한 기록”이에요. Git은 그 기록과 변경 내용을 관리하는 도구예요.
저장소 · main · 브랜치
저장소는 코드와 기록을 모은 공간이에요. main은 대표 작업 줄기, 브랜치는 따로 작업할 수 있도록 나눈 줄기예요.
병합 · PR
병합은 다른 줄기의 변경을 합치는 일이에요. PR은 합칠 변경을 팀원이 확인할 수 있도록 올리는 요청이에요.
MVP
먼저 써 보며 핵심 아이디어를 확인할 수 있는 첫 버전이에요. 최종 기능을 전부 넣은 완제품이라는 뜻은 아니에요.
React · 프론트엔드
사용자가 보는 화면과 버튼 반응을 만드는 쪽이에요. 이 프로젝트는 그 화면을 React라는 도구로 만들어요.
Django · 백엔드
화면 뒤에서 요청을 받고 자료를 처리하는 쪽이에요. 이 프로젝트는 Python의 Django라는 도구를 사용해요.
API · DRF
API는 프로그램끼리 요청과 답을 주고받는 약속과 통로예요. DRF는 Django에서 이런 통로를 만들기 쉽게 해 주는 도구예요.
DB · PostgreSQL · 모델
DB는 자료를 보관하는 곳, PostgreSQL은 이 프로젝트의 보관 도구예요. 모델은 어떤 정보를 어떤 칸에 저장할지 적은 코드예요.
마이그레이션 · ERD
마이그레이션은 보관 구조의 변경을 실제 DB에 적용하는 순서 파일이에요. ERD는 정보들 사이의 연결을 그린 그림이에요.
mock · 프로토타입
mock은 실제 정보 대신 흐름을 확인하려고 넣은 예시예요. 프로토타입은 사용 모습을 미리 살펴보는 시안이에요.
LLM · ML · 라우터
LLM은 문장을 이해하고 만드는 AI, ML은 자료를 학습해 분류·예측하는 방법이에요. 라우터는 요청을 맡을 곳으로 보내는 안내 역할이에요.
환경변수 · CODEF
환경변수는 컴퓨터별 연결 주소·설정값을 코드와 따로 두는 방법이에요. CODEF는 금융기관 조회 연결을 돕는 외부 서비스예요.
