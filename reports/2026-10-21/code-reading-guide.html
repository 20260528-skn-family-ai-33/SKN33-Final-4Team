한 파일을 여는 순서

① 맨 위 설명 주석 → ② 가져오는 다른 파일(import) → ③ 중요한 함수나 화면 이름 → ④ 표시 문구·숫자 → ⑤ 클릭했을 때 하는 일. 어려운 문법은 표시해 두고 먼저 흐름을 따라가세요.

‘주석’은 실행 명령이 아닌 설명글이에요. JavaScript는 //, Python은 #로 시작하는 줄이 대표적이에요. 주석도 오래될 수 있으니 실제 코드와 함께 확인하면 좋아요.

화면 코드에서 자주 만나는 이름

Page.jsx는 화면 한 장, Popup.jsx는 팝업, .css는 모양이에요. .jsx는 JavaScript 코드 안에 화면 모양도 함께 쓰는 파일입니다.

서버 폴더의 같은 이름

api.py는 요청 처리, models.py는 저장 구조, mock.py는 예시 자료예요. admin.py는 관리 화면, migrations/는 저장 구조 변경 기록입니다.

03 / 숫자 하나의 여행

홈의 ‘30,900원’은 어디서 올까요?

현재 코드에서 확인되는 길이에요. 아래 네 버튼을 누르면 각 단계에서 실제로 오가는 것을 볼 수 있어요.

“홈에 필요한 자료를 주세요.”

HomePage.jsx에서 useApi('/api/home/')를 호출해요. utils/api.js의 fetch가 요청을 보냅니다.

보내는 것: 홈 자료를 읽겠다는 요청. 개인의 실제 잔액을 이 화면 안에서 계산하는 단계는 아니에요.

5
홈이 30,900원으로 표시해요

frontend/src/pages/HomePage.jsx · 80행 · frontend/src/utils/money.js · 3행

+
앞으로 연결할 길: 서버 → 저장된 실제 자료

models.py에는 보관할 구조가 있어요. 하지만 현재 홈 요청은 그 구조를 통해 실제 회원의 자료를 읽지 않아요. 실제 자료를 읽는 처리를 api.py에 연결해야 합니다.

점선 상자 = 아직 홈 흐름에 연결되지 않은 부분
확인 질문 · 화면에 30,900원이 보이면 실제 계산이 끝난 걸까요?

현재 홈에서는 아니에요. 서버 파일에 적혀 있는 예시 숫자를 표시합니다. 하지만 거래의 취소 금액 차감이나 예산 방향의 비율 계산처럼 실제 계산을 하는 코드도 따로 있어요. ‘예시 자료를 쓴다’와 ‘모든 기능이 가짜다’는 같은 말이 아닙니다.

11 / 작은 용어 사전

코드 옆에 두고 보는 쉬운 설명

컴포넌트 · props
컴포넌트는 조립해 쓰는 화면 부품이에요. props는 부품에 전달하는 설정이나 값이에요. Layout에 제목을 넘기는 것이 한 예예요.
함수 · 호출
함수는 이름을 붙인 작은 작업 묶음이에요. 호출은 그 작업을 실행해 달라고 하는 일이에요.
상태 · useState
상태는 지금 선택하거나 입력한 값이에요. useState는 화면이 그 값을 잠깐 기억하게 해요. 영구 저장은 별도예요.
API · 요청 · 응답
API는 자료를 주고받는 약속과 통로예요. 요청은 “주세요/저장해 주세요”, 응답은 그에 대한 결과입니다.
JSON
이름표와 값을 짝지어 주고받는 자료 모양이에요. 예: {"daily": 30900}. 화면 디자인 자체가 아니라 자료를 담아요.
GET · POST · PATCH
GET은 자료 읽기, POST는 만들기·처리 요청, PATCH는 일부 수정에 주로 써요. 현재 화면용 주소는 GET 읽기 중심이에요.
라우터 · Route
주소나 질문을 보고 담당 화면·함수를 고르는 안내 장치예요. 화면 라우터와 챗봇 라우터는 담당 대상이 달라요.
DB 모델 · ForeignKey
모델은 자료 표의 설계 코드예요. ForeignKey는 “이 거래는 이 회원의 것”처럼 다른 표의 자료를 가리키는 연결 칸이에요.
세션 · 쿠키 · CSRF
세션은 서버가 기억하는 로그인 상태, 쿠키는 브라우저에 남기는 작은 표식이에요. CSRF 토큰은 저장 요청이 다른 사이트에서 몰래 온 것인지 막는 확인 표식이에요.
camelCase · snake_case
여러 단어를 붙이는 두 이름 방식이에요. livingBudget과 living_budget처럼 표기만 다르고 같은 뜻일 수 있어요.
Vite · 프록시
Vite는 화면 개발과 실행을 돕는 도구예요. 여기서 프록시는 개발 중 /api 요청을 Django 서버로 넘기는 중간 전달 역할이에요.
검증 · 테스트
입력 조건이 맞는지, 계산이나 동작이 기대한 결과를 내는지 확인하는 일이에요. 이번 문서는 코드를 읽은 결과이며 프로젝트 기능을 다시 실행해 시험한 보고서는 아니에요.
이 문서는 저장소의 현재 코드와 로컬 Git 기록을 바탕으로 만든 읽기 자료입니다. 실제 금융기관 조회·DB 변경·프로젝트 실행 검사는 이번 정리에서 수행하지 않았습니다.
