# 정답 문제 (3단계 평가 세트)

검색이 맞는 정책을 몇 등에 내놓는지 채점하는 시험지다. RRF 상수 · 지역 가산점 · 키워드 가중치를 바꿀 때마다 같은 시험지로 다시 채점해서 좋아졌는지 본다.

## 파일 모양 (`questions.json`)

| 칸 | 뜻 |
|---|---|
| `date` | 채점 기준일. 날짜가 바뀌면 마감된 정책이 빠져 점수가 저절로 바뀌므로 고정한다 |
| `id` | `q01` 처럼 겹치지 않게 |
| `kind` | `구체` · `막연` · `두고민` · `없음` · `지역` · `이사` (아래 표) |
| `query` | 사용자가 챗봇에 쓸 법한 문장 그대로. 나이 · 소득 · 지역이 들어 있어도 된다 (실제 사용자도 그렇게 쓴다) |
| `region` | 에이전트가 최종으로 검색할 시군구. 이름 일부나 코드 (`동탄구`, `41597`). `중구`처럼 여러 곳이면 오류가 나니 코드로. 문장에 시도만 있거나 지역이 없으면 버튼으로 고른 곳을 가정하고 `note` 에 적는다 |
| `keywords` | 사람이 뽑은 키워드. 4단계 자동 추출과 비교할 기준 |
| `answers` | 정답 묶음 목록 `[["번호"], ["번호A", "번호B"]]`. 한 `[]` 안 번호는 하나만 나와도 그 묶음을 찾은 것. 재등록 번호(같은 이름)와 이름만 다른 같은 제도는 한 `[]` 안에. `두고민`은 주제마다 한 묶음(예: 생활비 정책 전부 / 주거비 정책 전부). `없음`이면 `[]` |
| `profile` | 문장에 드러난 사용자 조건 (선택): `{"age": 26, "job": "미취업자", "gender": "female", "specials": ["중소기업"]}`. 문장에 없는 값은 적지 않는다. 있으면 자격 불충족을 뺀 뒤 순위(`·자격` 줄)와 정답 정책의 자격 판단도 보여 준다 |
| `note` | 왜 이게 정답인지 메모 (선택) |

| kind | 예 | 보는 것 |
|---|---|---|
| 구체 | "자격증 시험 비용 지원받고 싶어" | 기본 실력 |
| 막연 | "돈 모으고 싶어" | 4단계 질문 다듬기가 필요한지 |
| 두고민 | "면접 교통비랑 정장 빌리는 거" | 정답 묶음이 둘. `묶음` 점수로 둘 다 찾는지 |
| 없음 | "우주 비행사 되고 싶어" | 맞는 정책 없음 기준을 정할 재료 (1위 거리) |
| 지역 | 그 지역에만 있는 정책을 찾는 질문 | 지역 가산점이 필요한지 |
| 이사 | "다음 달에 부산 해운대로 이사 가는데 받을 수 있는 지원 있어?" (사는 곳은 강남구) | 문장에 지명이 들어가도 검색이 되는지. 4단계에서는 지역을 맞게 읽는지도 본다. 1~2개만 |

검색은 지역을 문장에서 읽지 않고 `region` 으로 받는다. 실제 에이전트에서는 버튼으로 고른 사는 곳이 기본이고, 문장 속 지역 읽기는 4단계에서 만든다. 문장 속 지역이 사는 곳과 다르면 조용히 바꾸지 않고 `[해운대구 기준으로 보기] [사는 곳(강남구) 기준으로 보기]` 버튼으로 확인한다 (4 · 6단계). 그래서 `이사` 질문의 `region` 에는 확인 뒤 최종으로 검색할 지역을 적고, 사는 곳은 `note` 에 적는다.

자격 판단 · 대화 맥락 · 지어내기 거절처럼 검색 순위로 채점할 수 없는 질문은 `agent_questions.md` 에 모아 두고 5단계 이후 답변 평가에 쓴다.

## 순서

1. 질문 · 지역 · 키워드를 먼저 쓴다. `answers` 를 `[]` 로 두면 "정답 미정"으로 채점에서 빠진다
2. 정답 후보 찾기 — **검색 결과가 아니라** 단어가 들어간 정책 전체를 본다:

```bash
python manage.py policy_find 응시료 자격증 --region 동탄구 --date 2026-11-10 --detail
```

   - 맨 앞 20자리가 정책번호. `같은 이름 2건` 이면 두 번호를 한 묶음에
   - 단어를 바꿔 가며 여러 번 찾는다 (정책은 "응시료"라 쓰고 사람은 "시험비"라 쓴다)
   - 정답 기준: **"질문한 사람이 이걸 보면 '내가 찾던 거다'라고 할까?"** 관련 있는지만 본다. 자격(나이 · 소득)은 5단계가 거른다
   - 빼는 것: 다른 지역 사업이 전국 코드로 들어온 것(`(광양시) …`, 경북 K보듬 등 — 담당 기관을 본다), 질문한 사람이 될 수 없는 대상 전용(장병 · 전세사기 피해자 · 자립준비청년 등), 운영 · 연구 · 통계 사업
   - 기준일에 마감된 정책은 후보에 없어서 정답이 될 수 없다. 진짜 정답이 마감이면 `note` 에 적는다
3. 형식 · 번호 확인 (임베딩을 부르지 않는다):

```bash
python manage.py policy_eval --check
```

4. 채점 (실제 임베딩, 질문 20개면 몇 원 수준):

```bash
python manage.py policy_eval
python manage.py policy_eval --only q01 q02
python manage.py policy_eval --auto   # 4단계 질문 읽기(LLM, 질문마다 1회)로 '자동' 칸도 채점
```

`자동` 은 LLM 이 뽑은 검색 문장 · 키워드로 찾은 순위다. 목표는 사람이 뽑은 `키워드` 점수에 가까워지는 것. 표 아래 "질문 읽기"에 사람 키워드와 LLM 이 읽은 결과가 나란히 나온다. LLM 답은 실행마다 조금씩 달라서, 프롬프트를 비교할 때는 여러 번 돌려 본다.

## 점수 읽기

| 지표 | 뜻 |
|---|---|
| Hit@3 | 정답이 3위 안에 든 질문 비율. 추천이 3개라 가장 중요하다 |
| Hit@10 | 10위 안 |
| 30위 안 | 후보 30개 안에 들었나. 5단계 자격 검사가 여기서 고르므로 빠지면 되살릴 수 없다 |
| MRR | 정답 순위 역수의 평균 (1위 1, 2위 0.5, 3위 0.33 …) |
| 묶음 | 정답 묶음 중 30위 안에 든 비율. 두고민 질문에서 둘 다 찾는지 |

마지막 표 `1위 거리` 는 정답 없는 질문과 정답 있는 질문의 1위 거리가 갈리는지 본다. 갈리지 않으면 거리 말고 다른 '맞는 정책 없음' 기준이 필요하다.
